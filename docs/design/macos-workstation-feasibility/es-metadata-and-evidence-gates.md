# macOS native evidence: metadata map and remaining gates

Updated 2026-10-18. Target: modeled macOS 26 arm64 workstations. This is the implementation plan supplement for native evidence, not a claim that ES generation is available. Public source material remains ignored under `sample_data/macos/`; tests and examples are independently authored. No further local-log inspection or capture is authorized without asking the user first.

## Initial ES field-to-owner map

This maps the implemented wire types in `formats/macos_endpoint_security.py`, not every Apple API event. All fields below are required by the currently admitted wire profiles unless optionality is stated. Historical v6 supports exec/fork/create/rename, v9 supports exec/exit, and v10 supports fork only. These are decoder admissions, not generation support. Do not expand the version/event table merely because an API field exists.

| Native fields | Canonical owner / existing facts | Remaining work and acceptance |
| --- | --- | --- |
| `schema_version`, `version`, `event_type`, `action_type` | Source profile plus canonical occurrence type; codec has strict discriminants. | Explicit build/collector/event admission. Unsupported combinations fail before emission; notification output never pretends to be AUTH callbacks. |
| `action.result.result_type`, `action.result.result.auth` | Outcome of the specific modeled operation, projected through the notification profile. | Carry an explicit observed result; do not infer Gatekeeper rejection or a policy authority from the numeric result alone. |
| `time`, `mach_time` | Canonical timestamp, boot state and `generation/timing/macos.py`. | Retain UTC/native precision and explicit timebase. No generator-host clock/filesystem consultation; never claim modeled precision is empirical calibration. |
| `seq_num`, `global_seq_num` | Collector-instance observation state, not process state or a generic global event ID. | Implement per-client/per-event-type and per-client counters respectively. Define subscription, loss and restart boundaries; checkpoint counters; render filtering must not renumber retained rows. Do not conflate exporter filtering with kernel drops. |
| `thread.thread_id` | Exact event-time thread identity; State already owns Mac thread allocation and exec replacement. | Bind the performing thread to the occurrence. Preserve through delayed rendering/recovery; a process's current primary thread is not a universal substitute. |
| `process.audit_token` and child/target tokens: `auid/euid/egid/ruid/rgid/pid/asid/pidversion` | `ProcessIdentity`, `PosixProcessCredentials`, audit adoption and host-owned PID versions; `ESAuditToken.from_process_identity` exists. | Require complete event-time snapshots. v6/v9 named objects and v10 eight-word arrays remain distinct. Missing audit origin is not root or the unset sentinel. |
| `parent_audit_token`, `responsible_audit_token` | Parent lifetime relationships exist; full event-time native snapshots do not. | Retain the parent and responsible identities separately. Apple's responsible-token contract permits self when responsibility is absent or the responsible process has exited; implement that rule at observation time, not by unconditional parent substitution. Test parent exit, responsible exit and PID reuse. |
| `ppid`, `original_ppid` | `ProcessIdentity.parent_pid` currently provides one parent value. | Separate current and original parent; original stays fixed after reparenting. Preserve exact parent lifetime, credentials and audit PID version in historical observations. |
| `group_id`, `session_id` | Revision 217 adds optional host-scoped POSIX group/session lifetimes, explicit bootstrap/setsid/setpgid, inherited membership and leaderless reservations. Login/audit IDs remain separate. | State, dispatch/eCAR, rollback and checkpoint contracts are implemented. Production boot/session/job composition and group-safe launchd closure remain open. Unknown membership must reject a complete native snapshot; never substitute LogonID or ASID. |
| `codesigning_flags`, `is_platform_binary`, `is_es_client`, `cs_validation_category` | `MachOCodeSignature` supplies static signing identity; runtime policy/collector membership is incomplete. | Separate runtime flags and validation category from release signature and installed software. Do not infer client attachment from installation. Category is required in v10 and absent in current v6/v9 profiles. |
| `signing_id`, `team_id`, `cdhash` | Release-owned `MachOCodeSignature`; CDHash is distinct from content SHA hashes and Mach-O UUID. | Preserve required nullable signing/team fields. Add explicit unsigned/ad-hoc/runtime-executable cases before claiming them; no guessed all-zero hash to fill missing truth. |
| `start_time` | `ProcessIdentity.started_at` is the lifetime start, separate from execution start. | Six-digit UTC serialization; same-PID exec retains lifetime start. Test PID reuse and exec after checkpoint. |
| `executable`, `tty` | Installed/runtime binary identity and path exist; session/shell state exists. | Every file uses the stat mapping below. `tty` is required nullable: null means modeled no terminal, not unknown. Model terminal devices only for admitted session kinds. |
| File `path`, `path_truncated` | Binary/artifact placement and canonical paths. | Event-time path presentation, explicit truncation, modeled aliases/case policy and rename ownership. Do not hash a path into an inode. |
| Stat `st_dev/st_ino/st_rdev`, `st_mode/st_nlink/st_uid/st_gid`, `st_flags/st_gen` | Deployment, mount/storage and file-version owners; full local native stat identity is absent. | Add stable volume/object/device identity and permissions. Content version differs from file-object identity; rename preserves the object, replacement need not. No host `stat()` calls. |
| Stat `st_atimespec/st_mtimespec/st_ctimespec/st_birthtimespec` | Canonical file transitions; content timestamps alone are insufficient. | Model access/modification/metadata-change/birth separately with immutable observation snapshots; ctime is not creation time. |
| Stat `st_size/st_blocks/st_blksize` | `FileContentIdentity.size_bytes` covers logical content size. | Explicit allocation/block policy; no assertion that compressed or sparse files occupy logical-size bytes. Initial supported policy must be documented. |
| `event.fork.child` | Authenticated fork transition already owns parent/child execution identities and inherited credentials. | Project both complete snapshots from the same transition; prevent ordinary process creation from masquerading as an observed fork. |
| `event.exec.target` | Authenticated before/after exec identities and thread replacement exist. | Bind source and target to one lifetime and transition. A denied image replacement cannot publish a successful target. |
| Exec `script`, `cwd`, `args`, `env` | Optional exact argv and an ordered environment vector now belong to immutable `ProcessIdentity` execution snapshots and retained process state. Current-directory facts partly exist; complete native cwd/script facts do not. | Fork inherits known argv; exec replaces it or preserves unknown status when omitted. No splitting display text. Explicit argv and its canonical display must agree. Environment preserves order, duplicates, literals and known-empty versus unknown. | `event.exit.stat` | `PosixProcessExit` now carries an explicit terminal result through authenticated State termination, canonical projection and retained checkpoint history. | Bounded Darwin conversion distinguishes exit code, termination signal and core flag. Absent facts remain unknown; raw unsupported statuses cannot become canonical terminal results. No automatic success default or inference from signal delivery. Current-build ES exit profile and full native process snapshot remain gated. |
| Create `destination_type/destination.existing_file/acl` | Process-owned file creation and content versions. | Only referenced existing-file/null-ACL variant admitted; a new-path create variant requires its own reference and canonical allocation semantics. |
| Rename `source/destination_type/destination.existing_file` or `destination.new_path.dir/filename` | Canonical file placement/version owners need complete local rename composition. | Preserve the tagged destination, overwritten-object identity and same-volume object continuity; cross-volume copy/delete is not a rename shortcut. |

The [Apple sequence-counter contract](https://developer.apple.com/documentation/endpointsecurity/es_message_t/seq_num), [global counter](https://developer.apple.com/documentation/endpointsecurity/es_message_t/global_seq_num), [original parent](https://developer.apple.com/documentation/endpointsecurity/es_process_t/original_ppid), [responsible identity](https://developer.apple.com/documentation/endpointsecurity/es_process_t/responsible_audit_token) and [POSIX session field](https://developer.apple.com/documentation/endpointsecurity/es_process_t/session_id) govern these distinctions. Documentation fetched now can contain newer API fields; availability must be checked against the selected profile before adoption.

## Execution order and decision points

1. AUTH-1 is implemented without weakening existing fixtures or recovery guards; retain its regression coverage. The subsequent revision 215 routine run passes cleanly.
2. Independent ES-M2 terminal-result, exact-argv and environment-vector slices are implemented. The POSIX group/session owner and source projection are implemented. Next compose explicit membership through boot/session/job bundles and add parent/responsible ownership; reuse these owners for PERSIST-1. Add source-specific state only where the collector genuinely owns it.
3. Complete ES-M2 and ES-O1, then admit each event family only after its field and reference gates pass. Fork's target-family reference does not prove exec/exit or a complete lifecycle.
4. Implement POLICY-1 independently of GK-R1. Record supported canonical outcomes even while native messages remain unavailable.
5. Revisit ES-R1/GK-R1 only for a concrete new public lead. If those remain the only route to completing requested native coverage, present a bounded lab-capture proposal for approval rather than repeatedly searching or claiming completion.
6. Run focused owner tests per slice, representative slow generation/recovery checks, routine suite and Ruff; retain Windows/Linux equivalence and old schema/pack compatibility gates. Update the capability matrix with implemented, experimental and validated scope separately.

No new top-level configuration is proposed. Canonical runtime facts belong in existing state/context/deployment owners; any necessary durable codec extension must explicitly read compatible older records or diagnose incompatibility. No product version bump, native artifact generation, private-log inspection or service activation is authorized by this supplement.

## Terminal-result implementation boundary

Revision 215 adds an internal optional terminal result without a scenario/configuration field. Normal exit, signal termination and core indication are separate facts. Existing close paths retain an unknown result, preserving their evidence; a modeled signal request alone cannot supply this result. Only an authenticated POSIX process termination can publish it. The bounded historical ES exit codec can convert this fact to/from Darwin wait-status integers, but neither the ES generator nor a new version/event profile is enabled. Stop/continue encodings and unsupported raw values remain preserved by the reader and cannot be promoted to terminal outcomes.

Apple's public [wait-status ABI](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/wait.h) and [signal declarations](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/signal.h) establish the conversion, not a macOS 26 eslogger capture. These pinned source references are stored only in the ignored acquisition directory with provenance. Tests are independently authored. Process checkpoint records advance to v8 with explicit lossless v7 migration: missing historical outcomes stay unknown.

## Explicit argument-vector boundary

Revision 216 carries explicitly supplied POSIX argv through creation, fork, exec, immutable observations and checkpoint restoration. It does not parse catalog/scenario command strings or add an authored field. Known argv requires its canonical shell-quoted display command; quoted spaces, empty later arguments and literal shell syntax retain their original argument boundaries. The admission budget is 256 arguments and 64 KiB of UTF-8 argument bytes including terminators; this is a modeled resource bound, not a claim about Darwin's kernel limit. Missing argv remains unknown and a later exec cannot inherit the previous image's vector.

Loaded system-job activation consumes the existing launchd definition's exact arguments and rejects a missing or different vector even when other process fields look plausible. State running-process v9 and immutable process-identity v5 codecs explicitly migrate earlier records with absent argv. Environment, cwd, file descriptors and full native process snapshots still block an ES exec renderer.

## POSIX group/session implementation and remaining composition

Revision 217 implements the internal ownership primitives and bounded eCAR projection; production composition remains engineering work with no new personal capture prerequisite. Apple's archived [setsid](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setsid.2.html) and [setpgid](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setpgid.2.html) contracts establish group/session distinctions and transition restrictions; they do not validate current native messages. The [POSIX process-group lifetime definition](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap03.html#tag_03_283) explains why a leader's exit cannot retire a group that still has members.

| Owning layer | Required implementation and acceptance |
| --- | --- |
| State process identity and action cohort | Separate host-scoped group/session lifetime identity from numeric PGID/SID and from login/audit identity. Bootstrap only an explicitly known initial membership; unknown legacy membership stays unknown. Authenticated changes preserve before/after snapshots without pretending a group change is an exec. Test fork inheritance, exec preservation, session-leader restrictions and cross-session join rejection. |
| PID allocation and retained history | Keep a group/session's numeric ID reserved for its actual lifetime, including after leader exit. Reuse after retirement creates a different identity. Test same-number groups on separate hosts, leader exit with surviving members, final-member exit and allocation-watermark boundaries. Avoid scanning every process for every PID candidate. |
| Transaction and checkpoint ownership | Include membership indexes and reservations in cohort preview, commit, rollback and recovery. A failed publication must not leak membership or numeric reservations; a retry must not duplicate them. Historical source observations must retain their original membership after later transitions. Preserve old checkpoints as unknown membership where compatible. |
| Launch-job closure | Select exact admitted group members through this owner, then use existing process/service close transactions. Ancestry alone is insufficient: include an adopted member only if membership is proven and exclude a descendant that changed groups. Signal intent, actual terminal outcome and unload completion remain distinct. |

No scenario/configuration fields were added. The bounded internal bootstrap creates SID/PGID 1 for an explicitly admitted privileged PID-1 process at its creation frontier; it is not a claim about macOS kernel initialization or a production boot default. Zero-valued kernel membership is outside this initial profile. Fork inherits known membership; exec preserves it; setpgid supports self or a same-session child before exec; setsid creates a new session/group for a non-group-leader. Immutable before/after observations retain the same execution identity. Parent-controlled changes retain the actual actor, child target and both activity frontiers.

Explicit membership changes remain chronological within each touched group/session; same-process membership transitions require increasing times. Revision 219 admits out-of-order inherited starts and ordinary exits only within a still-live exact group lifetime. The retained frontier never moves backward, and final-member departure cannot retire the group before that frontier. Retired groups cannot reopen. This supports planner look-ahead without permitting backdated setsid/setpgid transitions. The implementation bounds retained per-process changes at 64 and numeric-ID epochs at 128 per open scheduling window; these are internal admission budgets, not OS limits. Closed reservations retire at the authoritative PID watermark. Unknown legacy membership stays absent. State checkpoint head 7 explicitly reads head 6 and unchanged version-6 allocator segments; process record 10 and identity record 6 upgrade older records with unknown membership.

Revision 219 composes explicit session creation into the existing Mac terminal login launch; the shell and subsequent children inherit that membership. This aggregate launch contract does not claim observed fork/setsid records. PID-1 and Terminal membership remain unknown unless explicitly modeled; no kernel initialization default or public configuration field is introduced.

Bounded launchd unload now prepares the exact known group (up to 256 members), orders children before parents through retained lifecycle identities, and commits State terminations plus service/binding closures atomically. Source projection authenticates each close against one shared receipt. Missing/extra members, changed State, external live descendants and hold-adjusted close times reject before mutation. Registry commit followed by a lost return retains a proof and completes State rather than rolling it back independently. Unknown membership retains the prior single-process guard.

Remaining acceptance: retain explicit service-group ownership after its leader/binding retires; distinguish current from original parent and support canonical reparenting before closing a parent with a surviving child; complete job launch and authored persistence orchestration. Actual initial boot membership and native ES metadata remain separately gated.

The group-unload implementation extends the authenticated service/process closure composite rather than looping over individual closes. Its preparation must bind an exact group lifetime and member set, detect membership changes before commit, close service bindings with those exact process identities, and preserve the shared rollback/recovery boundary. Cover a leader that exits before unload, members joining/leaving before preparation, stale membership after preparation, numeric-ID reuse, an external descendant in a different group, and injected failure before/after publication. Reparenting remains a separate prerequisite where closing a member would otherwise orphan a still-live child; do not weaken the existing child-before-parent lifecycle guard.

## Explicit launch environment boundary

Revision 218 adds an optional ordered UTF-8 string environment vector to process execution identity and retained State. Fork inherits it; exec replaces it, and omission remains unknown instead of reusing a prior image's environment. A known empty tuple is distinct from absence. Order, duplicate entries and literal values remain intact; no mapping conversion, shell expansion, parent inference for generic launches, or host-environment lookup occurs. The internal 256-entry/64-KiB limit is not an OS limit. Mutable in-process environment changes and arbitrary byte-level envp fidelity remain outside this profile. Process record 11 and identity record 7 explicitly migrate older records with unknown environment. No scenario/configuration field or native ES renderer is added.
