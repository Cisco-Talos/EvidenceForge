# Adaptive generation resource forecast

## Objective

Replace the static generation workload rejection and public `--allow-large-workload` requirement
with an always-visible, machine-aware forecast. Validation and generation must report projected
peak memory, available RAM plus swap, projected output size, and destination filesystem capacity.
When projected pressure is material, output a low, medium, or high advisory warning and continue.

## Design

- Keep deterministic allocation-free scenario workload estimation.
- Inspect live RAM, swap, cgroup memory limits, and destination filesystem capacity through
  `psutil` plus Linux cgroup control files.
- Use versioned calibration coefficients in `config/resource_forecast.yaml` rather than fixed CLI
  admission limits. Model v2 is fitted from scaled assessment runs and validated against both
  interpolated and independent mixed-format holdouts.
- Provide `scripts/calibrate_generation_resources.py` to collect peak RSS, output bytes, elapsed
  time, and workload-estimate inputs from representative scenarios for future coefficient updates.
- Model bounded emitter queues, canonical retained state, email expansion, format fan-out, and
  Sysmon's retained event dictionaries separately.
- Compare expected projections with capacity after reserving configurable memory and disk
  headroom. Classify pressure as low at 70%, medium at 85%, and high at 95% of usable capacity.
- Always render the informational forecast first and any warnings immediately afterward.
- Preserve the former CLI option as a hidden compatibility no-op for existing scripts; it is no
  longer documented, required, or behavior-changing.
- Keep YAML/include/path/archive boundaries as hard safety errors. The evaluator's independent
  corpus-capacity guard is out of scope.

## Verification target

- Unit coverage for forecast ranges, RAM-plus-swap pressure, disk pressure, all three severity
  levels, cgroup constraints, source-aware Sysmon memory, and warning presentation order.
- CLI coverage proving both validation and generation display the forecast and omit the former
  option from public help.
- Existing workload tests updated to prove long scenarios are admitted without override.
- Full non-slow suite plus Ruff check and format verification before commit.

## Verification result

- Focused forecast, workload, collection-profile, and CLI suite: 62 passed.
- Final full non-slow suite: 5,382 passed and 41 skipped in 323.18 seconds.
- Ruff check: all checks passed.
- Ruff format verification: all 468 files formatted.
- Minimal real validation printed the complete forecast with no warning at low pressure.
- Calibration harness completed a real `zeek_conn` generation measurement and reported peak RSS,
  generated bytes, elapsed time, and workload-estimate inputs.
- `generate --help` and `validate --help` no longer expose `--allow-large-workload`.

## Empirical calibration

The harness generated the six-hour `iteration-test-expanded-ids` assessment scenario at 1× and
2× duration for Zeek-only, Sysmon-only, Windows Security-only, and full-format profiles. It then
generated safe 4× source-isolated profiles. Filtered source profiles intentionally remove the
storyline and red herrings so raw events targeting another emitter cannot invalidate isolation;
the full profile retains all 46 storyline steps.

Observed 1×/2×/4× peak RSS in MiB:

| Profile | 1× | 2× | 4× |
|---|---:|---:|---:|
| Zeek | 136.0 | 155.3 | 189.4 |
| Sysmon | 130.7 | 154.5 | 210.6 |
| Windows Security | 154.0 | 191.1 | 226.3 |
| Full | 205.9 | 253.8 | not used |

The full 4×/24-hour run was stopped by the generator's existing bounded Linux PID-allocation
contention guard, not by memory or disk pressure. The failure demonstrates a nonlinear scenario
duration boundary and is intentionally not treated as a resource-forecast calibration point.
The highest successful peak remained 253.8 MiB, far below system pressure thresholds.

Model v2 uses a measured fixed interpreter/generator cost, emitter-format fixed costs,
baseline-occurrence slopes, explicit-occurrence slopes, and source-specific output rates scoped to
all, Windows, Linux, or role-eligible systems. The prediction interval remains wider for disk than
memory because topology and role mix change how many canonical events each source actually renders.

Held-out results:

| Holdout | Memory actual / expected | Memory error | Disk actual / expected | Disk error |
|---|---:|---:|---:|---:|
| Zeek 3× | 177.8 / 164.1 MiB | −7.7% | 17.55 / 21.99 MiB | +25.3% |
| Sysmon 3× | 192.6 / 176.9 MiB | −8.2% | 15.12 / 17.76 MiB | +17.5% |
| Security 3× | 225.7 / 201.1 MiB | −10.9% | 45.63 / 52.80 MiB | +15.7% |
| Full assessment 1.5× | 237.1 / 244.0 MiB | +2.9% | 67.05 / 68.08 MiB | +1.5% |
| Independent full-coverage APT | 197.9 / 180.7 MiB | −8.7% | 43.95 / 35.45 MiB | −19.3% |

Every held-out actual value landed inside its lower/upper forecast range. Expected-memory error was
2.9–10.9%; expected-disk error was 1.5–25.3%. This is sufficient evidence for the warning model
without driving the host near actual memory or disk exhaustion.
