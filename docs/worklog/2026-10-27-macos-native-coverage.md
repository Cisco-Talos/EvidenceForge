## Ordering repair design

The engine constructs canonical activities in category passes, so source delivery cannot assume
that preparation order equals modeled kernel occurrence order. Native collection must first
retain immutable occurrence facts in the same exact journal as canonical publication, then
sequence those facts chronologically. This separates canonical process lifecycle commits from
collector delivery without changing event time or assigning invented delays.

The source-owned ingress is an internal sorted spool, not an exported native log.
It retains counter-only unsupported/filtered phases as well as complete native message bodies;
native sequence numbers are assigned only after canonical producers have completed. Exact source
snapshot admission shares the existing action-cohort sink journal. The ordinary native output
adapter receives fully sequenced immutable records during restartable finalization. Checkpoints
retain ingress runs through the existing spool participant; memory stays bounded by sorter pages.
Direct explicitly ordered collector APIs retain their current strict contract.

No native gate is widened by this ordering work. A format-selected or decoder-successful source
does not establish that all real activity has a native producer.
