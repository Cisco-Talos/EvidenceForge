## November 10 publication-condition repair

The unused legacy branch is intentionally skipped for modern snapshots. GitHub
propagates skipped ancestors through a dependency chain unless a job condition
includes a status function; the publisher inherited implicit `success()` even
though the `always()` aggregate publication gate had passed. See
[GitHub's dependency semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idneeds).

Override that implicit status check with `always() && !cancelled()`, explicitly
requiring both version validation and the selected publication gate to succeed.
Keep the existing failed/cancelled/skipped/missing-policy negative gate tests and
add a publisher-condition regression that fails on the original workflow.

This is an orchestration correction on dev, not a changed a6 release snapshot.
Use the documented manual recovery entry point against the existing immutable
tag. Every gate/build/publisher still checks out `bbcf9cd6`; no source overlay or
tag movement is permitted. No draft assets exist to replace. The recovery run
will build and verify its own installers under the existing publication contract.
