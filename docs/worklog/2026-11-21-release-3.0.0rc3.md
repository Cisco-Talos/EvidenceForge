# 3.0.0rc3 qualification

The release candidate will build on `dev`. Preserve the rc1 and rc2 tags as internal
release snapshots. Run release coverage and native Studio CI, the full extended suite,
and release-mode installer verification on the exact committed rc3 snapshot before
creating its tag. See [release instructions](../releases.md#alpha-beta-and-release-candidates).

## Changes prompted by rc2

- Windows Security 4688 distinguishes creator credentials from the target process token.
  Cross-source evaluation uses the target account when available and retains the creator
  fallback for same-token and older records.
- Samba logoff truth matches the native `smbd` service-close message. Use the worker PID
  and share where canonical evidence supplies them.
- Web access expectations match client IP, method, path and source-native time. The
  Lantern case had two clients request the same path in the same second. Keep support
  for the older stored selector and evaluate the evidence using the current one.
- Deferred RDP finalization fixtures use a constructed engine to exercise real seed and
  effective-configuration ownership. The CLI boundary regression controls authored
  placement so background jitter cannot hide the mixed cohort it is testing.
- The macOS process regression explicitly exercises both shell commands and reconciles
  sequence gaps against recorded source omissions. Exact fork, command exit, and
  completeness checks still apply.
- The extended Linux profile uses measured expensive case timings from all five rc2
  JUnit reports. It keeps the previous estimates for short cases and budgets timed-out
  expanded benchmarks so the shard planner can separate them. The workflow gives each
  shard 120 minutes. Subprocess guards remain finite, and planned-suspension coverage
  uses four simulated hours with the established 24-hour checkpoint cadence.
