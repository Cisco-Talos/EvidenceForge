# Loop 83 family contract — typed Linux shell pipeline process ownership

- **Owning abstraction:** canonical process execution in `ActivityGenerator` plus the existing Linux pipeline stage parser/timing planner; `typed_handlers.process.handle_process` is the storyline adapter.
- **Invariant:** a successful typed Linux shell process with a bounded, explicit pipeline creates canonical process records for executable pipeline stages under the authored shell PID; dependent storyline network activity resolves to the actual effect-owning final executable; the final child remains active through its dependent flow; and the foreground parent waits until its pipeline child terminates. Pipeline materialization does not perturb the shared storyline RNG stream.
- **Entry-path inventory:** (1) typed storyline `ProcessEventSpec` currently emits one process through `ActivityGenerator.generate_process`; (2) Bash-history process telemetry splits and emits pipeline groups using `_linux_command_process_groups_from_shell` and `plan_linux_pipeline_stage_times`; (3) catalog baseline activity uses `_linux_catalog_process_groups_from_shell_command` and the same timing planner; (4) direct process action calls represent a single executable and must not recursively expand command lines. This change adapts only typed shell-command intents into the established stage parser/planner and process action; ordinary single processes remain unchanged.
- **Consumer inventory:** `StateManager` process/parent/lifecycle identity; eCAR and Linux process renderers; later typed network events using `_last_storyline_process_for_system`; network-observation planning; evaluation and the neutral-output probes.
- **Layer rationale:** process identities, parentage, and flow ownership are canonical state/action semantics. Fixing eCAR would only hide the absent process tree and preserve wrong PID ownership in the flow. A dedicated source-native emitter patch is not appropriate.
- **Sibling risks:** preserve existing baseline pipeline expansion without duplication; keep builtins from being mislabeled as external executables; bound parsing and stage count; never infer stages outside shell quoting; ensure the final shell child lives through dependent network telemetry and parent/child close ordering. Current target pipeline has external `base64 -d` and `bash` stages; Bash builtin `echo` should not be represented as an external image.
