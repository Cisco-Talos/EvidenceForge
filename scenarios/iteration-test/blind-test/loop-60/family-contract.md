# Connect-only scanner application semantics

Classification: sibling_defect / scanner intent contract. Threat48/51 independently found client payload on plain nmap -Pn -sT with no version/script/data option. Owner: process-command scanner plan and action-bundle transport construction, before canonical network admission. The current probe sampler invents application payload for every state, including closed and silent targets, and guesses passive service labels from port inventory.

Invariant: an ordinary connect-only scan sends no client application payload. Unestablished REJ/S0 probes have no application payload either direction. A server-first banner may be observed and classified according to validated configured service semantics; client-first protocols do not emit unsolicited application responses. A successful plain connect is terminated by the client's reset, consistent with Nmap's documented connect behavior. Version/script/data options remain distinct explicit application-probe intent rather than silently eliminating valid probing. The contract does not pretend to implement full NSE or every version-detection phase.

Entry paths: modeled/unmodeled process-command targets, explicit address/CIDR, discovery-only versus connect, -sV/-sR/-A/-sC/script/data options, option-value operands and server-first SSH/MySQL/SMTP/FTP. Preserve target coverage, scan fan-out and process-to-network identity. Shared helper operates on pre-admission semantic fields; never edit Zeek rows. Add config/loader/negative-validator coverage for server-first services. Validate a non-sample explicit application-probe sibling and rendered zero-client-byte property across all command-owned plain connect flows.

Primary official references: https://nmap.org/book/scan-methods-connect-scan.html documents connect without application data, an optional SSH banner and immediate client reset; https://nmap.org/book/man-version-detection.html distinguishes -sV/-sR/-A interrogation from port-state discovery. No commands from logs are executed.
