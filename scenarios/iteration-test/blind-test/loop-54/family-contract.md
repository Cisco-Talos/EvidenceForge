# Inspected proxy client TLS transport budget

Classification: new_family / canonical action-channel byte ownership. Owner: ProxyTransactionActionBundle physical client transport and ExplicitProxyOpenPreparation/reused-request admission. Proxy request/response totals describe decrypted HTTP messages; CONNECT setup bytes describe plaintext control. Neither includes the secure tunnel handshake or TLS records. The canonical TCP payload must include CONNECT control + modeled client-leg TLS handshake + encrypted application records, once per physical transport.

Use a data-driven scoped fresh TLS1.3 client handshake budget (current browser/curl profile), shared pure record expansion (5-byte TLSCiphertext header,1-byte inner content type,16-byte AEAD tag; max16384 plaintext fragment), and exact request-local versus aggregate distinctions. Attach/freeze resulting setup wire totals in the private open preparation before admission. Reused requests consume encrypted application bytes from the same authoritative channel budget and do not repeat the handshake. Proxy plaintext totals remain request-local; no log-row-derived sibling generation or emitter counting.

Entry paths: first browser-group request, request-local HTTPS, reused/deferred admission, cache/local responses and failure paths. Siblings: plaintext HTTP must not gain TLS overhead; opaque CONNECT already has separately modeled opaque payload and must not be counted as inspected HTTP. Denied/auth-required CONNECT before TLS cannot receive a successful handshake. Preserve entity sizes, source observation gaps, transport lifecycle ordering and retained registry authentication/checkpoint contracts. Validate tunable profile ranges and run config validation. Tests must cover zero/short/large messages, fragmentation, group request reservations, reuse and plaintext/failure controls.
