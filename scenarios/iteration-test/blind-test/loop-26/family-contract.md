# Selected family contract — bounded canonical native launch phases

Selected from actual24 Detection Engineer review and independently verified by
all four actual reviewers in deliberation. This is distinct from fixed authored
command-group fractional timestamps: nine generated launchd/xpcproxy/app chains
all have visible gap2=2*gap1 within one microsecond. ProcessExecutionService
_prepare_finder currently samples one readiness gap and linearly splits four
canonical stages at 0,1/3,2/3,1. The third stage is a credential transition not
one of the three native fork/exec observations, producing the visible 1:2 ratio.

Owner: canonical process action scheduling plus a pure bounded phase allocator.
Invariant: retain the existing sampled first/final readiness anchors and exact
four-stage order; allocate interior stage time from separately scoped positive
transition weights, rather than equal subdivisions. Compute once before State,
metadata directories, binary/process identities, retained source preparation or
native projection. Native birth, wall, Mach and eCAR times render that same truth.
No emitter jitter, scenario edits, new state/cache/quota/retention or raw RNG.
The modeled timing support is not an assertion of measured native latency.

Reuse the existing overlayable Finder readiness timing support for positive
transition weights with distinct sample keys through the existing engine timing
capability. The allocation is conditioned on the existing total budget; per-stage
weights are not claims of independent physical durations after conditioning.
Zero/negative sampled weights or an unrepresentable interval fail clearly.
Preserve explicit source-readiness deadline admission against the unchanged final
anchor. Freeze all phase times once in the existing retained startup so source
failure/retry cannot resample or duplicate canonical transitions.

Entries: all ordinary Finder launches through ProcessExecutionService, including
baseline desktop apps and authored VS Code; existing Terminal bootstrap already
has its own separately modeled stage delays and remains unchanged. Consumers:
MacosFinderStartup, identity/credential transitions, ES ingress/coverage, eCAR,
Mach clock projection, exact retained replay and source filtering. Inventory also
found equal-split SSH descendant teardown and RDP logout schedules; they are
separate continuation owners to assess in subsequent loops, not silently patch
alongside this Finder change. Pure allocator may be reused by those owners only
after their own lifecycle/minimum/deadline/recovery contracts are verified.

Validation: native multi-launch before control confirms fixed ratio; new control
requires variable stage allocation while final readiness/birth anchors stay
unchanged and all canonical/native/credential order holds. Existing Finder
relationships, credentials, generation, incomplete coverage and per-phase source
recovery; sibling Terminal startup and native clock tests; exact RNG census,
manifest, config validation and Ruff. No full routine/release gate claimed.
Source563 remains frozen until actual25 generation and postprocessing EXIT0.
