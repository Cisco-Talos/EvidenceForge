# Detection Engineer — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 86
**Synthetic-Confidence Score:** 76

## Executive Summary
The reviewed telemetry is likely synthetic, although it is substantially more realistic than a simple generated dataset. The formats parse cleanly, Windows event versions and field sets are largely correct, identifiers are stable, process and session lifecycles are coherent, and Zeek protocol records correlate correctly with their parent connections. Those strengths make the material superficially production-like.

The strongest contrary evidence is a systemic causal inversion in the domain-controller Security logs: Kerberos ticket processing is recorded before the matching Windows Filtering Platform permit event for the same client address, client port, server port 88, protocol, and host. This occurs in 1,173 of 1,192 matched DC-01 transactions and 1,154 of 1,161 matched DC-02 transactions. The same WFP records have normal ordering relative to Sysmon network events, so the inversion is specific to the Kerberos construction rather than a general timestamp convention. Repeated semantically implausible Sysmon CreateRemoteThread and ImageLoad combinations provide independent supporting evidence.

## Evidence For Synthetic
- **[hard_contradiction] Systemic Kerberos-before-network-permit ordering:** In `DC-01/security.jsonl`, 1,192 Kerberos events (4768, 4769, or 4771) could be matched to an Event 5156 record by exact client IP and source port on destination port 88; 1,173 of those WFP permit events occur after the KDC event. In `DC-02/security.jsonl`, 1,154 of 1,161 matched transactions have the same inversion. For example, DC-01 records Event 4769 for `WS-EBROOKS-01$` from `::ffff:10.10.1.33:56911` at `2024-03-18T17:27:01.779790Z`, then records Event 5156 permitting that same tuple at `17:27:03.517980Z`, 1.738190 seconds later. DC-02 records Event 4769 for `WS-PPATEL-01$` from `10.10.1.32:63121` at `17:33:13.303684Z`, followed by its matching permit at `17:33:14.215219Z`. The pattern is too prevalent and too consistently directional to be explained by occasional scheduler jitter or timestamp precision.

- **[environment_or_collection_plausibility] Benign Sysmon Event 8 semantics appear fabricated:** Across the Windows Sysmon files, 12 CreateRemoteThread records use structurally valid fields but include unlikely routine behaviors. `DC-01/sysmon.jsonl` records `MsMpEng.exe` creating a remote thread in `winlogon.exe` at `2024-03-18T15:13:30.5281645Z`, with `StartModule=C:\ProgramData\Microsoft\Windows Defender\Platform\4.18.24010.7-0\MpOav.dll` and `StartFunction=AmsiScanBuffer`. Other repeated pairs include `WmiPrvSE.exe` into `svchost.exe` with `RtlUserThreadStart`, and `svchost.exe` into `taskhostw.exe` with `ScServiceMain`. These functions are plausible symbols in isolation but are not credible as a recurring benign remote-thread vocabulary across unrelated hosts and processes.

- **[environment_or_collection_plausibility] VMware provider module is assigned to LSASS on multiple servers:** Sysmon Event 7 repeatedly shows `lsass.exe` loading `C:\Program Files\VMware\VMware Tools\vmStatsProvider.dll`, including `DC-01/sysmon.jsonl` at `2024-03-18T15:44:35.2258009Z` and `DC-02/sysmon.jsonl` at `2024-03-18T13:04:35.1544890Z`, with similar records on `FILE-SRV` and `MAIL-FIN`. The file name and path describe a VMware statistics/performance provider, while the selected consuming process is the Local Security Authority. Repeating this unusual pairing across distinct servers is more consistent with a module-to-process assignment rule than observed host behavior.

- **[contract_gap] One explicit-credential event carries a conflicting source address:** `WS-MCHEN-01/security.jsonl` Event 4648 at `2024-03-18T14:50:24.1983858Z` attributes a local `runas.exe` action by `marcus.chen` to `IpAddress=10.10.1.99`. The host's network evidence consistently assigns `10.10.1.31` to WS-MCHEN, while `10.10.1.99` is used by LT-MRIVERA. The subject LogonID `0x6b920ba` is Marcus Chen's established WS-MCHEN session, not a visible remote session. Although a pre-window remote-control path cannot be excluded, the event conflicts with the otherwise stable endpoint identity model.

- **[contract_gap] Three isolated process-create companions are absent from an otherwise near-exact dual-provider profile:** Of 940 Security Event 4688 records, 937 have a matching Sysmon Event 1 with the same image, parent PID and image, command line, and LogonID. The exceptions are `WS-DRAMIREZ-01/security.jsonl` `dllhost.exe` PID `0x19c0` at `2024-03-18T12:54:38.2438280Z`, and `WS-MCHEN-01/security.jsonl` `conhost.exe` PID `0x1d80` at `13:20:16.0292942Z` plus `svchost.exe` PID `0x23dc` at `17:33:06.6928673Z`. This is low-impact evidence because production collection loss can cause the same result, but the dataset otherwise behaves like a paired-event contract.

- **[weak_signal] Backup-service placement is operationally unusual:** Explicit-credential events show `Veeam.Backup.Service.exe` installed and acting from both `DC-01` and `MAIL-FIN`, including access from DC-01 to DB-PROD at `2024-03-18T12:26:35.6437426Z` and from MAIL-FIN to DC-02 at `12:18:40.7570105Z`. Distributed Veeam roles can make this possible, so this is not decisive, but the placement on a domain controller and mail server is atypical enough to warrant corroboration.

## Evidence For Real
- All sampled JSONL records parse, and all Windows event XML documents parse. Security and Sysmon events use credible providers, channels, versions, timestamp precision, and per-Event-ID field sets. Examples include Security 4624 version 2, 4688 version 2, and 5156 version 1, plus Sysmon Event 1 version 5, Event 3 version 5, Event 8 version 2, and Event 22 version 5.

- Windows authentication semantics are detailed and internally plausible. Across 830 successful logons, the observed LogonType mix is 414 service, 381 network, 19 remote interactive, eight unlock, five interactive, and three NewCredentials. Service logons use `Advapi`/`Negotiate` and `services.exe`; network logons use Kerberos or NTLM with remote addresses; and local interactive or unlock events use `User32`. The 17 failed logons distinguish bad-password status `0xc000006d/0xc000006a` from disabled-account status `0xc0000072`.

- Process data has strong lifecycle integrity. Security Event 4688 and Sysmon Event 1 agree on all compared process fields for 937 matched pairs, while Sysmon timestamps lead Security by approximately 35 to 1,242 milliseconds, a credible cross-provider delay. No duplicate Sysmon ProcessGuid creation, parent-after-child relation, termination-before-creation, or dependent event preceding the visible process was found. Security Event 4689 reports `Status=0x0` for all 803 process exits.

- The DC-01 Security-log clearing sequence is notably convincing. At `2024-03-18T17:41:57.190Z`, `cmd.exe /c wevtutil cl Security` is created; `wevtutil.exe` follows at `17:41:57.624Z`; Event 1102 is then recorded at `17:42:01.267Z`. The Security EventRecordID resets to 1 and resumes monotonically from 2. This is coherent both causally and structurally.

- File-server audit chains preserve source-native identifiers and ordering. In `FILE-SRV/security.jsonl`, a representative sequence at `2024-03-18T12:04:06Z` begins with Event 5145 for Aisha Johnson from `::ffff:10.10.2.11:50879` accessing `Projects\2023\action-items.xlsx`, followed by Event 4656 opening handle `0xdfb4fc0e`, Event 4663 recording write access mask `0x2`, and Event 4658 closing the same handle. Comparable chains recur with varied users, paths, ports, masks, and handles.

- Zeek linkage is exceptionally sound without relying on mere completeness as an authenticity claim. The three sensors contain 20,261 `conn.log` records. Every checked DNS, HTTP, SSL, SMTP, SMB mapping, and SMB file record references an existing connection UID, agrees with its connection tuple, and occurs after connection start. Companion delays also vary by protocol: core DNS appears 0 to 6.097 milliseconds after connection start, HTTP from 7 milliseconds to 3.626 seconds, SSL from 14 to 638 milliseconds, and SMB file activity from 237 milliseconds to 1.778 seconds.

- TLS visibility reflects protocol details. Non-resumed TLS 1.3 connections commonly lack visible certificate chains, while non-resumed TLS 1.2 connections usually carry X.509 records; resumed sessions generally omit new chains. This distinction is more nuanced than mechanically attaching certificates to every SSL record.

- Network outcomes have realistic texture. Core Zeek connection states include 9,021 `SF`, 2,023 `S0`, 148 `RSTO`, 80 `RSTR`, 25 `OTH`, 22 `REJ`, 18 `S2`, and 12 `S3`; the DMZ and database sensors likewise contain successful, unanswered, reset, and rejected traffic. DHCP records use 3,600-, 7,200-, and 14,400-second leases with nonuniform renewal intervals rather than fixed global cadence.

- Cross-layer perimeter behavior is semantically plausible. A DMZ Zeek connection from `185.220.233.25:21880` to `10.10.3.10:80` starts at `2024-03-18T12:00:18.060541Z` with `conn_state=S0` and no payload. `WEB-EXT/syslog.log` records a UFW block of the same tuple at `12:00:18.183903Z`, while `fw-perimeter/cisco_asa.log` records ASA connection 1681558 and tears it down after 30 seconds with zero bytes and reason `SYN Timeout`. The records correctly distinguish perimeter admission/NAT, host rejection, and sensor observation.

- Linux SSH evidence includes connection, acceptance, PAM session-open, and session-close phases, plus failed and invalid-user attempts. No accepted authentication was found before its corresponding connection. Pre-window sessions sometimes contribute only a close event, which is appropriate for the bounded six-hour window and was not treated as a lifecycle defect.

## Detailed Analysis
**Scope and volume.** The reviewed data spans approximately `2024-03-18T12:00:00Z` through `18:00:00Z`. It includes ten Windows Security/Sysmon pairs, endpoint eCAR telemetry, eleven Linux syslog sources, three Zeek sensors, ASA firewall logs, two Snort alert streams, proxy access logs, and web access logs. Exact high-volume counts include 6,659 DC-01 Security events, 4,323 DC-01 Sysmon events, 5,835 DC-02 Security events, 3,635 DC-02 Sysmon events, 11,354 core Zeek connections, 8,432 DMZ connections, 19,656 ASA lines, 2,678 proxy records, and 763 web records. These volumes are not themselves suspicious for a six-hour enterprise sample.

**Windows schema and Event ID semantics.** Field shapes are stable by event type and the sampled values satisfy the main semantic contracts. Event 4624 authentication-package and process combinations vary appropriately by logon type. Event 4688 token-elevation fields agree with MandatoryLabel: 683 system-integrity processes use `%%1936` and `S-1-16-16384`, 239 medium-integrity processes use `%%1938` and `S-1-16-8192`, and 18 elevated processes use `%%1937` and `S-1-16-12288`. Events 4768 and 4769 use plausible service names, ticket options, and AES/RC4 encryption types, while Event 4771 failures use status `0x18`. No contradictory reuse of a Windows SID for different named principals was found.

**Causal ordering.** Process, file, logon, SSH, and Zeek protocol ordering is generally robust. The material exception is the KDC/WFP relationship. A KDC cannot process a request before the corresponding packet is admitted by the local filtering platform. Audit delivery can introduce limited apparent reordering, but the observed effect is not rare or bidirectional: it affects 98.4% of matched DC-01 Kerberos transactions and 99.4% of matched DC-02 transactions, commonly by hundreds of milliseconds and sometimes more than one second. Both event families are in the same Security channel. Moreover, matching WFP records usually precede Sysmon Event 3 on these systems—3,390 of 3,725 matched DC-01 records and 2,857 of 3,034 DC-02 records—so WFP is not globally timestamped late. The defect is localized to Kerberos transaction construction.

**Identifier and lifecycle integrity.** Zeek UIDs are unique in the connection logs and resolve correctly from child records. Process GUIDs and eCAR event IDs are unique in the reviewed scope. eCAR process termination, actor, and logout records do not precede their corresponding create or login records. Apparent workstation processes associated with sessions whose only visible 4624 is a later Type 7 unlock were treated as pre-window sessions, not as contradictions. This avoids penalizing bounded telemetry for omitted history.

**Source-native behavior.** Zeek connection states, timing, TLS chain visibility, DHCP renewal intervals, proxy CONNECT semantics, web `304` byte notation, ASA teardown reasons, and Snort fast-alert formatting all show meaningful source-specific behavior. Conversely, the questionable Sysmon Event 8 pairs appear to select plausible Windows functions without preserving what those functions mean in a cross-process thread-creation event. The repeated LSASS/`vmStatsProvider.dll` image-load pairing has the same signature: correct-looking fields combined in an operationally unlikely relationship.

**Collection-profile consistency.** This is not a thin dataset, and missing event types were not used as evidence. The three absent Sysmon process-create companions are mentioned only because the same profile produces an exact companion for 99.7% of Security 4688 events. Even so, isolated event loss is ordinary in real telemetry and this gap carries little weight. The verdict is therefore driven primarily by concrete timing and semantic defects, not by completeness, narrative clarity, or ease of reconstruction.

- **Temporal patterns:** 6 — Most lifecycle and protocol timing is strong, but the near-universal Kerberos-before-WFP inversion on both DCs is a major causal defect.

## Recommendations
- Make local packet-admission time the lower bound for KDC processing. For every Event 4768, 4769, or 4771 tied to a modeled network request, generate or timestamp the matching Event 5156 before KDC authentication and preserve that order after provider-specific delay is applied.
- Replace generic Sysmon Event 8 templates with behavior-specific remote-thread cases. Validate source/target process permissions, architecture, target lifetime, start module ownership, and start-function semantics; do not use normal service entry points or AMSI scan functions as decorative thread targets.
- Constrain image-load generation by process role. VMware performance-provider modules should be assigned only to credible provider hosts, and security-process module loads should come from realistic authentication, cryptographic, or security-package paths.
- Derive Event 4648 network fields from the actual initiating session and endpoint. If `10.10.1.99` represents remote control of WS-MCHEN, emit the supporting remote-session evidence and bind the explicit-credential event to that session; otherwise use the local endpoint address or the source-native null representation.
- Apply source-observation loss coherently to process lifecycles. If isolated Sysmon Event 1 records are intentionally dropped, ensure dependent Event 3/5/7/8/10/11/13/22 records do not imply a missing creation, and document the collection profile used for that loss.
- Preserve the successful realism features: protocol-dependent Zeek delays, TLS-version-aware certificate visibility, nonuniform DHCP renewals, bounded-window lifecycle handling, source-native firewall outcomes, and shared process/session identifiers.
