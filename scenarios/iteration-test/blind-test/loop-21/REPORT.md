## Family contract, ownership and actual output

The console planner derives free terminals from current and bounded retained
canonical process lifetimes. It prefers an existing idle getty, treats already
materialized future execution as a reservation, and rejects exhaustion of the
configured terminal inventory. A new optional typed `linux_console` policy
selects this bounded adapter; frozen absence preserves the legacy child-login
path. Six default VTs follow systemd's default inventory; canonical tty1–tty63
validation is a native naming bound, not a larger runtime/retention quota.
Inventory overlays replace that new field's full list; unrelated merge rules stay
unchanged. GDM and SSH retain their distinct owners.

`ProcessExecutionService.execute_existing_posix` uses the shared State execution
builder and exact cohort/registry/source transaction. Getty→login preserves PID,
object identity, original birth and parent while creating the new execution
epoch before PAM/session readiness. A qualified root-owned login is the human
session's explicit `process_tree_root`; child admission and generic/strict teardown
share an exact predicate covering host, PID, root principal, root/uncaptured boot
authentication, initial/current images, ordinal, argv and timing. Root credentials
are not rewritten to the human account. The human session owns teardown logically;
AuthContext and process identity retain the process's actual authentication.

The rendered console census finds **10 same-lifetime getty→login execs and zero
separate child-login creates**, versus ten separate-child records before this
repair. Ten of fifteen native PAM opens join these visible execs; other starts
can be outside the slice or use different local authentication paths. This is a
descriptive census, not a new reviewer completeness requirement. The unmodified
Windows duration census still has 754 matched Sysmon pairs, minimum 3.029 s and
none under one or three seconds; that family is selected for loop 22.

Entry paths include baseline/local-auth noise, authored local logons, root-owned
console shell admission, normal and sudo-qualified logoff, source filtering and
State/checkpoint recovery. Consumers include canonical process/session identities,
eCAR CREATE/MODIFY/TERMINATE, PAM/logind messages, foreground parenting and exact
source publication. No emitter-only PID substitution, source gap, new persistent
State field/history cache or quota increase is used.
