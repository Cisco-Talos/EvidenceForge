# Loop 84 family contract — foreground Linux pipeline parent lifecycle

- **Owning abstraction:** canonical process lifecycle and dependent-transport holds for Linux pipeline process groups, coordinated by the shared Linux shell command/action model and the storyline pending-termination queue.
- **Invariant:** a foreground shell executing a modeled pipeline remains live until its pipeline children finish. A child that owns a dependent network connection remains live through that connection; its foreground parent close follows the child's terminal event. Asynchronous/daemonized child processes remain free to outlive their parent when explicitly modeled as such.
- **Entry paths:** (1) typed storyline process adapter expands explicit shell commands into pipeline groups; (2) Bash-history process telemetry and catalog baseline activity already use the shared pipeline resolver/planner; (3) canonical network connections extend the effect-owning process through transport close; (4) storyline process termination queues and generic lifecycle finalization close parents/children.
- **Consumer inventory:** StateManager parent/process identity, foreground close finalizers, lifecycle authority, storyline termination queue, eCAR/Linux process renderers, endpoint FLOW ownership, and lifecycle tests/probes.
- **Layer rationale:** the wrong close order is produced by independent canonical lifetimes and deferred close scheduling after a child transport extends its activity. It is not an emitter timestamp issue. The pipeline contract and lifecycle owner must communicate the exact group/child dependency to the pending parent close.
- **Sibling risks:** do not hold unrelated parent/child relationships; preserve stop/watermark behavior and bounded lifecycle memory; ensure terminal events remain child-before-parent and source-local observation decisions remain coherent; cover a non-storyline pipeline sibling path.
