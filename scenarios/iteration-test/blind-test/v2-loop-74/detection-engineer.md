# Detection Engineer — Authenticity Assessment

## Verdict

**Assessment:** Synthetic
**Verdict Confidence:** 86
**Synthetic-Confidence Score:** 74

## Executive Summary

The records are unusually strong at source-native structure and most correlations survive detailed parsing, but two repeated, log-visible contract failures are difficult to reconcile with production telemetry. Sub-millisecond Windows lock/unlock cycles lack the successful Type 7 logons seen for normal unlocks in the same files, while several `systemd-resolved` instances continue emitting successful UDP DNS after explicitly entering TCP-only fallback; those defects, reinforced by repeated Linux baseline quotas, support a likely-synthetic assessment.

## Evidence For Synthetic

- [hard_contradiction] Two Windows sessions lock and unlock faster than an authentication can occur. In `WS-AJOHNSON-01.meridianhcs.local/windows_event_security.xml`, Event 4800 at `2024-03-18T17:47:57.2578026Z` is followed by Event 4801 at `17:47:57.2580206Z` for `aisha.johnson`, LogonID `0x2721d61`, SessionId `2`: only 0.218 ms. In `WS-MCHEN-01.meridianhcs.local/windows_event_security.xml`, Event 4800 at `15:50:29.4516506Z` is followed by Event 4801 at `15:50:29.4528037Z` for `marcus.chen`, LogonID `0x6b6f926`, SessionId `1`: 1.1531 ms. The other four lock/unlock cycles last 182-2,184 seconds, making these two repeated outliers materially different from normal session behavior.
- [contract_gap] Neither sub-millisecond Event 4801 has its required visible successful unlock logon. The AJOHNSON file's only Type 7 Event 4624 for `0x2721d61` is at `17:34:38.3196335Z`, before the later lock. The MCHEN file has Type 7 events at `14:30:18.9415406Z`, `15:42:38.4212805Z`, and `17:49:27.1693606Z`; none accompanies the `15:50:29.4528037Z` unlock. By contrast, the four credible unlocks are preceded by same-LogonID Type 7 records 0.213-0.511 seconds earlier, so the collection demonstrably records this companion event.
- [contract_gap] Resolver state contradicts endpoint and Zeek transport evidence. `MAIL-CLIN-01.meridianhcs.local/syslog.log` at `2024-03-18T12:21:41.233461Z` says PID `15516` is using “TCP instead of UDP+EDNS0” for DNS server `10.10.2.11`. Yet `MAIL-CLIN-01.meridianhcs.local/ecar.json` at `12:24:21.436Z` identifies that same PID and `/usr/lib/systemd/systemd-resolved` sending UDP from `10.10.2.26:45569` to `10.10.2.11:53`; `zeek-core/dns.json` and `zeek-core/conn.json` at `12:24:21.457019Z` confirm UID `C8Donm5oHBXsrSakoPc`, `proto:"udp"`, `rcode_name:"NOERROR"`, and `conn_state:"SF"`. There are 63 same-PID UDP DNS flows to that same server after the fallback message and no later resolver resumption message in the visible syslog.
- [contract_gap] The resolver contradiction repeats independently. `LOG-MON-01.meridianhcs.local/syslog.log` ends a sequence at `12:25:46.083310Z` with TCP fallback for `10.10.2.10`, after which its eCAR shows 14 UDP DNS flows from the same PID `23770` to that server. `WS-OHADDAD-01.meridianhcs.local/syslog.log` declares TCP fallback for `10.10.2.10` at `13:01:18.020091Z`, followed by 17 same-PID UDP DNS flows, starting at `13:07:14.539Z`; neither file contains a later resumption record.
- [distribution_texture] All ten hosts that log `systemd-resolved` emit exactly four resolver feature-state messages during the six-hour window, generally as two selections from the same “degraded UDP,” “degraded TCP,” and “grace period over” templates. The exact four-record quota appears on workstations, mail servers, a proxy, web server, application server, file server, and monitoring server despite sharply different DNS volumes and roles.
- [distribution_texture] The Debian `sysstat` CRON texture is mechanically uniform across the Linux fleet: the exact command `(sysstat) CMD (command -v debian-sa1 > /dev/null && debian-sa1 1 1)` appears every 30 minutes at a host-specific fixed minute, with 10-12 occurrences per host. Individual slots disappear while surrounding syslog continues—for example, `PROXY-01` has `13:36:00.189Z` and `14:36:00.315Z` but no `14:06` execution; `MAIL-EDGE-01` lacks the `13:36` and `17:06` slots; `WEB-EXT-01` lacks `14:31` and `17:31`. Repeating the same cadence plus apparently probabilistic isolated omissions across unrelated hosts is generator-like texture rather than ordinary fleet scheduling.

## Evidence For Real

- Windows XML is structurally convincing. The observed Security Event IDs use coherent versions and field sets: 4624 version 2 has the expected 27 fields; 4688 version 2 includes `NewProcessId`, `ProcessId`, `ParentProcessName`, and `MandatoryLabel`; 4768/4769 carry plausible ticket options, AES/RC4 encryption types, addresses, ports, and status values. Sysmon correctly varies field capitalization between Event 8 (`SourceProcessGuid`) and Event 10 (`SourceProcessGUID`) and uses plausible per-event versions.
- Of 988 Security 4688 records and 987 Sysmon Event 1 records, 987 match by host, decimal/hex PID, image, and time. Every matched Sysmon process creation precedes its Security counterpart by 35-899 ms, and no visible Sysmon parent, termination, network, module, registry, file, process-access, or remote-thread reference occurs before a visible creation of the same ProcessGuid.
- Process metadata is OS-aware rather than globally copied. The same Windows binary has version-appropriate hashes across builds: `taskhostw.exe`, for example, separates `10.0.17763.1`, `10.0.19041.1`, `10.0.20348.1`, and `10.0.22621.1` into four distinct hash sets. Paths, integrity levels, SIDs, GUIDs, LogonIDs, and PID encodings parse correctly.
- Zeek records have strong native integrity. Across 20,495 `conn.json` rows, all 4,359 DNS, 3,704 HTTP, 2,628 SSL, and 362 SMB child records with UIDs resolve to a same-sensor connection and have matching four-tuples; no child timestamp precedes its connection. All 1,083 TLS certificate references resolve to local `x509.json` records, and all certificates are valid at observation time.
- Zeek connection accounting is physically coherent: no TCP/UDP record violates the minimum IP-byte overhead implied by payload and packet counts. State/history mixtures include `SF`, `S0`, `RSTO`, `RSTR`, `REJ`, partial states, UDP `Dd`, and ICMP, rather than one success-only template. TLS includes TLS 1.2/1.3, RSA/ECDSA certificates, resumed sessions, and certificate omission patterns appropriate to resumed and TLS 1.3 traffic.
- The SMB chain is especially credible. UID `Ch8KpPY8KWFBbarlDt` opens at `2024-03-18T12:01:43.606837Z` from `10.10.1.34:62333` to `10.10.2.20:445`; mapping, open, read, and files records follow at `12:01:43.706103Z`, `12:01:44.119716Z`, `12:01:44.264495Z`, and `12:01:44.321895Z`. FUID `FWBxMyApUC0ovOEFk`, size `42773`, filename `Procedures\performance-summary-v2.xlsx`, and the endpoint's LogonID `0xf62df9a` remain coherent across Zeek, Security 4624/5145/4656/4663/4658, and eCAR.
- Cisco ASA syntax and lifecycle are strong: all 19,553 lines parse as `%ASA` messages with consistent PRI/severity. Connection IDs are strictly sequential from `1681558` through `1688988`; 7,430 of 7,431 builds have a later teardown, with no orphan teardown, no endpoint mismatch, and no duration/timestamp mismatch. The sole open connection, ID `1688495` built at `17:31:19`, can legitimately extend past the collection window.
- Native timestamp precision varies by source as expected: Windows SystemTime uses 100-ns-style precision, Sysmon `UtcTime` uses milliseconds, eCAR uses epoch milliseconds, Zeek uses fractional epoch seconds, RFC 5424 syslog uses UTC fractions, and access/ASA logs use second precision.

## Detailed Analysis

The permitted directory contains a six-hour slice, approximately `2024-03-18T12:00Z` through `18:00Z`, covering 19,355 Security events, 12,118 Sysmon events, 34,620 eCAR records, 34,516 Zeek records, 19,553 ASA messages, 171 Snort alerts, 3,756 syslog lines, 3,417 access-log lines, and 634 bash-history lines. The source mix spans ten Windows systems, eleven Linux systems, three Zeek sensor views, two Snort views, and a perimeter firewall. Volumes are differentiated by role: the domain controllers dominate 5156/Kerberos telemetry, the Exchange-like Windows mail host has Exchange processes, the Linux mail hosts show Postfix/Dovecot, the file hosts show SMB, and the web/proxy hosts carry corresponding access records.

Windows Security schemas are generally accurate. Aggregate counts include 818 Event 4624, 398 Event 4634, 33 Event 4625, 416 Event 4672, 988 Event 4688, 829 Event 4689, 788 Event 4768, 2,131 Event 4769, and 12,548 Event 5156, plus low-volume 1102, 4697/4698, and account-management events. Metadata is internally stable by Event ID: 4624 is version 2/task 12544; 4688 is version 2/task 13312; 5156 is version 1/task 12810. Event 1102 is correctly rendered under `Microsoft-Windows-Eventlog`, uses `UserData/LogFileCleared`, and resets DC-01's EventRecordID to 1. Successful type 3 logons generally have short, matched 4634 lifecycles; longer Type 2/10 sessions and pre-window terminations were not treated as defects.

The 4800/4801 defect is different from ordinary boundary effects. It occurs wholly inside the window, uses consecutive EventRecordIDs, and has both initiation and dependent event visible. Four ordinary cycles show the expected pattern: 4800, then a same-LogonID 4624 Type 7, then 4801 after a human-scale locked interval. The AJOHNSON and 15:50 MCHEN cycles instead collapse lock and unlock to microseconds and omit the intervening successful unlock logon despite that event class being collected. This is both an impossible visible timing relationship and a source-local contract gap.

Authentication and process evidence otherwise holds up well. The sampled 4625 records use coherent combinations: bad-password failures carry `Status 0xc000006d`, `SubStatus 0xc000006a`, and `FailureReason %%2313`, while disabled accounts use `SubStatus 0xc0000072` and `%%2307`. Kerberos records use plausible `0x11`, `0x12`, and `0x17` encryption types and varied ticket options rather than one constant. A representative DC-01 network logon for `marcus.chen` uses LogonID `0x538085b` at `12:06:14.2615385Z` and closes with Event 4634 at `12:06:20.4941818Z`. Security 4688, Sysmon Event 1, and eCAR process-create records align without PID/path inversions; eCAR consistently trails Sysmon creation timestamps by a plausible small sensor delay.

The resolver evidence provides the strongest cross-family synthetic tell. A `systemd-resolved` feature downgrade is per resolver/server state, so repeated successful UDP traffic from the same executable and PID to the same named DNS server conflicts with an unrescinded “TCP instead of UDP+EDNS0” state. MAIL-CLIN is not a one-packet probe: 63 later UDP flows span the remainder of the collection. The same pattern repeats on LOG-MON and WS-OHADDAD. Because endpoint eCAR attributes the flows to the exact resolver PID and Zeek independently records successful UDP request/response pairs, this cannot be dismissed as an unrelated application bypassing the resolver.

Zeek and network formats otherwise provide substantial production-like detail. `zeek-core/conn.json` has 11,712 rows with 9,446 `SF`, 1,954 `S0`, and smaller reset/reject/partial populations; `zeek-dmz/conn.json` has 8,345 rows with 5,498 `SF` and 2,620 `S0`, consistent with an exposed segment. DNS includes A, AAAA, PTR, SRV, TXT, MX, NS, and SOA plus NOERROR, NXDOMAIN, SERVFAIL, and REFUSED. TLS certificate chains match their references, non-resumed TLS 1.2 commonly has certificates, resumed sessions omit them, and TLS 1.3 lacks passively visible certificates. HTTP includes CONNECT, GET, and POST, multiple transaction depths, proxy authentication failures, cache statuses, and source-appropriate user agents.

ASA and Snort records also pass basic detection-engineering checks. ASA message IDs 302013/302014, 302015/302016, 305011/305012, 106023, and 302020/302021 use plausible text and severity. The first flow, connection `1681558`, builds inbound at `12:00:04` and tears down in the same second with `1824` bytes and `TCP Reset-O`; long-lived and SYN-timeout flows use durations consistent with line timestamps. Snort fast-alert lines have conventional timestamp, GID:SID:revision, classification, priority, protocol, and endpoint shapes, with signatures such as SID `2016149:3` for STUN and `2002910:4` for rapid HTTP/HTTPS attempts.

The remaining concern is distributional rather than structural. Exactly four `systemd-resolved` state messages on every resolver-logging host, combined with a shared half-hour `sysstat` command and scattered single-slot omissions, looks like quota-based baseline synthesis. Normal centralized configuration can explain a common command, but it does not readily explain identical resolver-event counts across ten heterogeneous systems or the same random-looking omission texture without accompanying host/collector interruption. Bash histories and process/application choices show more variation and include believable operator typos and role-specific commands, so they partially offset—but do not erase—that fleet-wide pattern.

## Realism Score by Category

- **Field format accuracy:** 9 — Windows, Sysmon, Zeek, ASA, Snort, syslog, access, and eCAR records parse cleanly with mostly source-native fields, encodings, and value shapes.
- **Temporal patterns:** 6 — Most ordering and precision are credible, but two microsecond lock/unlock cycles and fleet-wide schedule texture are material defects.
- **Cross-source correlation:** 8 — Process, SMB, network, certificate, firewall, and UID relationships are excellent; resolver state versus eCAR/Zeek transport is the major exception.
- **Behavioral realism:** 7 — Role-specific traffic and operator behavior are varied, but Linux resolver/CRON quotas repeat too mechanically.
- **Environmental consistency:** 7 — Host roles and source volumes broadly fit, while identical resolver event counts and unrescinded TCP-fallback states weaken the environment model.

## Recommendations

- If this were synthetic, model workstation lock and unlock as a guarded lifecycle: enforce a human-scale locked duration, emit a successful same-LogonID 4624 Type 7 before 4801 when that audit class is enabled, and reject lock/unlock timestamps that collapse below a realistic authentication floor.
- Treat `systemd-resolved` feature state as durable per host and DNS server. After logging “TCP instead of UDP+EDNS0,” route that resolver PID's queries to the named server over TCP until a logged resumption or a defensible probe-and-transition sequence occurs.
- Replace fixed four-event resolver quotas with state transitions driven by actual DNS outcomes and resolver retry logic. Hosts with no degradation should emit none; sustained failures should produce state-consistent retries and recoveries.
- Generate periodic CRON activity from explicit schedules and collection state. Do not probabilistically drop isolated executions while adjacent syslog remains intact; if an execution is absent, support it with a host/service interruption, a changed crontab, or a coherent collector gap.
- Preserve the existing strengths: Event-ID-specific Windows schemas, Sysmon capitalization/version fidelity, process and LogonID lifecycles, Zeek UID/FUID contracts, packet accounting, TLS certificate behavior, and ASA build/teardown pairing.
