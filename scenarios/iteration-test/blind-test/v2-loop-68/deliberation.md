## Key Agreements

- The corpus has substantial production-like strengths. The panel accepted the source-native Windows provider, event-version, SID, LogonID, GUID, PID, service, task, and Security-channel-reset semantics; the strong process and session ordering; and the differentiated host roles and activity volumes. The 964 of 965 matchable Sysmon Event ID 1 records that agree with Security 4688 on host, PID, and image were especially persuasive.
- The network layer is unusually strong. Sensor-local Zeek UIDs do not overlap, protocol companions generally resolve to valid parent connections, connection states and packet accounting are varied and viable, certificate chains and SAN/SNI relationships are coherent, and cross-sensor observations show stable clock offsets with small drift rather than copied timestamps. These features kept the panel from treating the corpus as low-quality or simplistic fabrication.
- Authenticity must turn on concrete visible contracts. The panel rejected narrative linearity, attack completeness, easy pivotability, and unusually complete cross-source matching as synthetic indicators in their own right. It also rejected filesystem timestamps, sanitized-domain resolution behavior, deliberately absent Sysmon event types, and generic source thinness when no visible volume, distribution, or required-companion contradiction follows.
- The Linux shell/TTY evidence and the Nmap execution footprint are materially different from those rejected weak indicators: each alleges that a visible process identity or command cannot produce the visible behavior attributed to it. Most panelists considered those two findings the central authenticity problems after cross-examination.
- Sparse source evidence remains conditional rather than automatically suspicious. The two dangling HTTP FUIDs are specific referential-integrity defects, but other missing file rows, DNS observations, or protocol companions can be explained by encryption, analyzer policy, caching, truncation, sampling, or collection boundaries unless the retained records make that explanation internally inconsistent.

## Key Disagreements

- **Threat Hunter.** The initial Synthetic 80/68 position rested principally on PID 2705215 running `nmap -sT -p 22,80,443,445,3306 10.10.2.0/24` without `-Pn` while core and DMZ sensors recorded nearly five ports against essentially all 254 addresses after the prior, separate `-sn` invocation found only nine responsive hosts. Secondary evidence was the missing `base64` and inner-Bash lineage for the reverse shell, with the socket assigned to the outer shell, and the fleet-wide pattern of short, one-file SMB connections. This reviewer uniquely joined command semantics to both endpoint process identity and the exact network footprint. The host review's 71 shell/TTY contradictions and eight close-only SSH lifecycles reinforced the Synthetic verdict; final position: Synthetic, verdict confidence 88, synthetic-confidence 82.
- **Detection Engineer.** The initial Inconclusive 82/43 position was driven by one same-session Security 4800-to-4801 interval of 406 microseconds and repeated all-`-` PE version-resource fields for 23 GoogleUpdater and 12 MpCmdRun executions despite complete hash sets. The specialist counterweight was exceptionally accurate Windows schema, provider, version, task, keyword, process, account, RDP, and channel-reset behavior. Cross-examination established that the lock pair is isolated, but the independent, fleet-wide shell/TTY contradiction and the command-level Nmap mismatch are not explained by those Windows strengths. Final position: Synthetic, verdict confidence 90, synthetic-confidence 78.
- **Network Forensics.** The initial Real 73/29 position emphasized 19,769 viable Zeek connections, realistic service-shaped durations, independent UIDs, clock skew and drift, DNS ecology, TLS/X.509 correctness, proxy-leg separation, and mixed success/failure states. Its strongest concerns were only two dangling HTTP FUIDs, six `files.missing_bytes` mismatches, and a successful 623,292,039-byte SMB upload on UID `CKMuqjtC97EMkXt71T` without file-operation companions; each retained plausible collection or encryption alternatives. The Threat Hunter's Nmap evidence exposed a blind spot: packet and Zeek-schema validity do not prove that the visible command could have produced the observed scan. Because an unseen global Nmap configuration could still force `-Pn`, and because the broader network corpus remains strong, the reviewer moved to Inconclusive rather than Synthetic; final verdict confidence 86, synthetic-confidence 58.
- **Host/EDR Forensics.** The initial Synthetic 96/92 position rested on 71 `sudo` records across 14 unchanged parent `/bin/bash` PIDs and 11 hosts whose TTY values rotate among multiple `pts/*` devices, plus eight in-window `sshd` process starts on five hosts that have only syslog close records and no same-PID connection, authentication, PAM-open, or session-open evidence. Repetitive fleet-wide `irqbalance`/`snapd` chatter was secondary. This specialist finding remained unrebutted: a continuing shell object does not migrate among controlling terminals, and ordinary bounded-window reasoning does not apply to session processes visibly created inside the window. Strong Windows and network findings narrowed the claim to a polished corpus with decisive Linux defects but did not change the verdict; final position: Synthetic, verdict confidence 97, synthetic-confidence 93.
- The remaining dissent concerns scope and burden of proof. Three reviewers conclude that repeated visible execution and identity contradictions outweigh broad realism. The Network Forensics reviewer gives more weight to the possibility of an unseen Nmap option and to the fact that the network records themselves obey source-native contracts, leaving that reviewer genuinely uncertain rather than aligned with the Synthetic majority.

## Most Convincing Evidence

1. **Fleet-wide shell/TTY identity contradiction — synthetic.** The same durable shell PID and actor UUID directly parents `sudo` processes whose syslog records rotate across two to four controlling terminals. On APP-INT-01, shell PID 2931384 produces four such children on `pts/0`, `pts/5`, `pts/2`, and `pts/3` within 38 seconds; the pattern spans 71 records, 14 shells, and 11 hosts. No independent session, replacement shell, or PID-reuse evidence supplies a plausible alternative.
2. **Nmap command-to-network contradiction — synthetic, subject to one testable alternative.** The separate `-sn` process receives only nine responses, yet the subsequent connect scan lacks `-Pn` and still produces approximately five TCP probes for virtually every usable address: 1,267 matching attempts in core and 1,269 in DMZ, overwhelmingly `S0`. Default Nmap does not carry host-discovery state between invocations. An unseen global configuration that forces `-Pn` is possible, but no report supplies evidence for it.
3. **Independent sensor and protocol behavior — real.** Core, DMZ, and DB observations use distinct UIDs, plausible stable offsets and drift, selective accounting differences, viable TCP histories, varied states, coherent service-shaped durations, and valid protocol ordering. TLS versions and ciphers agree, referenced certificate chains resolve, issuer/subject and SAN/SNI relationships hold, and explicit proxy client/origin legs correlate without reusing sensor identities.
4. **Source-native Windows lifecycle and identity semantics — real.** Security, Sysmon, and eCAR agree on process and session identities without visible reverse causality; RDP preserves transport-before-login order; account, service, task, and credential-access sequences are coherent; and Event 1102 correctly changes provider and resets the Security EventRecordID after `wevtutil cl Security`.
5. **In-window SSH close-only groups — synthetic contract gap.** Eight `sshd` PIDs are visibly created during the observation window but retain only a source-local close record. Because other SSH sessions in the same files contain connection, authentication, PAM-open, logind, and close evidence, this is more specific than generic source thinness, although selective record loss remains a possible alternative.

## Most Debated Points

- **Could global Nmap configuration explain the full sweep?** Yes in principle: a global configuration or wrapper that supplied `-Pn` would remove the command-contract contradiction. The panel nevertheless treated this as an unverified alternative, not a rebuttal. The decisive follow-up is to retain Nmap configuration or invocation telemetry and model the second command's own discovery behavior when no override exists.
- **Do missing process children prove a false reverse-shell lineage?** The visible pipeline requires an external `base64` process and an inner Bash that interprets the decoded `/dev/tcp` command, while the socket is attributed to the outer Bash. Short-lived process loss can explain an absent child, but it less readily explains both missing children and outer-process socket ownership when the same endpoint source captures even shorter subsequent commands. The point remained a strong contract gap, not a standalone hard verdict driver.
- **Are close-only SSH records an invalid lifecycle or selective collection loss?** A source can lose open records while retaining closes. The concern is the repeated one-sided selection across eight PIDs, five hosts, multiple users, and durations from roughly 28 seconds to more than 55 minutes despite rich surrounding SSH collection. The majority treated it as a high-value lifecycle defect; the panel did not elevate it to the same certainty as the shell/TTY contradiction.
- **How much weight belongs on one 406-microsecond lock/unlock pair?** It is not human-plausible for the same SID, LogonID, and SessionId, but it is one pair while other observed locks last 176.626 to 2,952.875 seconds. The panel retained it as a concrete hard outlier and quality-gate target, while declining to treat it as proof of a dataset-wide timing model.
- **Are SMB records too transactional?** The Threat Hunter found all 118 tree mappings on separate successful connections, with 89 of 102 file-bearing UIDs containing exactly an open plus one read or write; adjacent Finance files each receive new short TCP sessions. The Network reviewer also found incomplete file companions, including the 623 MB `ClinicalExports` upload, but noted that SMB3 encryption and analyzer policy can suppress file detail. Those alternatives explain missing companions better than the fleet-wide reconnection-per-file texture, yet unusual client behavior remains possible; the panel classified this as distribution evidence, not a contradiction.
- **Are blank PE resource fields synthetic?** Complete hashing can coexist with failed version-resource extraction, so `-` values are not individually invalid. Repetition across 35 executions of stable, well-known installed binaries on multiple hosts makes the all-or-nothing pattern mechanical enough to improve, but it remained medium-weight evidence.
- **Which observations were excluded?** No weight was assigned to narrative linearity, completeness, easy correlation, filesystem timestamps, sanitized domain resolution, deliberately absent Sysmon types, or sparse source families without a visible volume/distribution/required-companion contradiction. Proxy address reuse beyond visible DNS TTLs was also rejected as an authenticity finding because application-level caching is a direct plausible alternative.

## Improvement Recommendations (Consensus)

1. **Make controlling terminal immutable session state.** Bind each interactive shell PID and durable process identity to one TTY for its lifetime. A command may use a different `pts/*` only after a separately evidenced login/session and shell creation. Add a corpus-level invariant that fails when children of one continuing shell report multiple controlling terminals.
2. **Derive scan traffic from each visible Nmap invocation.** For `nmap -sT` without `-Pn`, emit that invocation's own discovery probes and restrict service probes to hosts it classifies as up. If a global option, wrapper, or configuration intentionally overrides discovery, retain explicit evidence of that override so the all-address footprint is explainable.
3. **Preserve source-local SSH lifecycle groups coherently.** For every in-window `sshd` session process, retain connection receipt, authentication result, PAM/session open, logind/session creation, and close records under the same PID when that source claims those facilities. If collection loss is modeled, apply it coherently and expose a defensible drop policy rather than repeatedly retaining only closes.
4. **Represent shell pipelines with actual process and socket ownership.** Emit `/usr/bin/base64`, the consuming inner Bash, their parent/child relationships and exits, and attribute `/dev/tcp` network activity to the process that opens the socket. Validate that visible command syntax, process lineage, and flow actor agree.
5. **Enforce human-plausible Windows lock state.** Add a minimum dwell-time check between Security 4800 and 4801 for the same LogonID and SessionId, and keep the session locked until a later explicit unlock. Preserve the realistic multi-minute lock durations already present elsewhere.
6. **Use stable, source-plausible PE metadata.** Populate Sysmon Event ID 1 version-resource fields for known installed binaries from stable binary identity. Where enrichment genuinely fails, vary the failure according to an explicit host, collector, file-access, or parsing condition instead of always emitting complete hashes alongside five placeholder fields.
7. **Improve SMB sessionization and make analyzer gaps explainable.** Reuse TCP sessions and tree mappings across adjacent file operations; include persistent/idle mappings, multiplexed accesses, reconnects, failures, and occasional incomplete sessions. Separately, ensure every emitted HTTP FUID resolves or carries a documented drop reason, and distinguish SMB encryption or analyzer truncation from an unexplained missing required companion.
8. **Retain the features that already withstand cross-examination.** Preserve native Windows provider/version semantics, process and logon identity continuity, Security-channel reset behavior, sensor-local Zeek identities, clock offsets and drift, varied packet/state accounting, TLS/X.509 contracts, role-shaped traffic volumes, and bounded-window lifecycle edges. Improvements should repair the identified execution contracts without flattening those source-specific differences.
