# Threat Hunter — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 80
**Synthetic-Confidence Score:** 68
## Executive Summary
The corpus is unusually strong at source-native formatting, lifecycle ordering, host-role differentiation, and cross-source pivotability. The reviewed scope contains 122,260 records: 32,990 eCAR records, 33,399 Zeek records, 29,613 Windows Security/Sysmon events, 19,039 ASA records, 3,769 syslog records, 2,450 proxy records, 852 web-access records, and 148 Snort alerts. Most attack and baseline chains survive detailed correlation without impossible timestamp ordering or identifier reuse.

The synthetic verdict is driven by a concrete command-to-network contradiction, not by the intrusion's coherence. `WEB-EXT-01.meridianhcs.local/ecar.json` records `nmap -sn 10.10.2.0/24` at 2024-03-18T13:40:44.657Z. Both `zeek-core/conn.json` and `zeek-dmz/conn.json` show 254 ICMP targets, of which only nine respond. A new process then runs `nmap -sT -p 22,80,443,445,3306 10.10.2.0/24` at 13:41:08.489Z without `-Pn`; nevertheless, the sensors record five-port connection attempts against essentially all 254 addresses. Default Nmap host discovery does not carry results between separate invocations and would not perform the requested port scan against 245 nonresponsive hosts. This is a high-weight execution-contract defect unless an unseen global Nmap configuration forced `-Pn`.

Two additional patterns support programmatic construction: the reverse-shell pipeline lacks the child-process lineage required by its own command while assigning the socket to the outer shell, and SMB activity is dominated by one-file, one-connection transactions rather than persistent mapped sessions. Those defects are partly offset by excellent Windows semantics, believable sensor skew, varied background distributions, clean lifecycle closure, and source-specific gaps.
## Evidence For Synthetic
- **[hard_contradiction] Nmap execution does not match its network footprint.** `WEB-EXT-01.meridianhcs.local/ecar.json` shows PID 2705168 running `nmap -sn 10.10.2.0/24` from 13:40:44.657Z to 13:41:07.654Z. In both core and DMZ Zeek data, that action probes all 254 usable addresses and receives only nine `SF` responses; 245 are `S0`. PID 2705215 then runs `nmap -sT -p 22,80,443,445,3306 10.10.2.0/24` from 13:41:08.489Z to 13:41:32.773Z. `zeek-core/conn.json` contains 1,267 matching TCP attempts from 13:41:11.465331Z through 13:41:19.576947Z: 251 hosts receive all five ports and three receive four, with 1,236 `S0`, 21 `REJ`, seven `SF`, two `RSTO`, and one `RSTR`. `zeek-dmz/conn.json` independently contains 1,269 attempts: 253 hosts receive all five ports and one receives four, with 1,238 `S0`. Without `-Pn`, a separate Nmap invocation should perform its own discovery and skip the hosts found down, not scan five ports on virtually the entire subnet.
- **[contract_gap] The reverse-shell process tree omits required children and misplaces socket ownership.** At 13:19:41.450Z, `WEB-EXT-01.meridianhcs.local/ecar.json` creates `/bin/bash`, PID 2702780, with `bash -c 'echo ... | base64 -d | bash'` under Apache PID 23966. The encoded content invokes another interactive Bash using `/dev/tcp/45.33.32.30/8443`. The corpus contains no `/usr/bin/base64` or nested `/bin/bash` process creation for this pipeline, yet at 13:19:45.139Z it assigns the outbound 10.10.3.10:49708→45.33.32.30:8443 flow directly to the outer shell. The same endpoint source records much shorter-lived child commands during the subsequent SSH session, making this particular lineage collapse difficult to explain solely as coarse process collection.
- **[distribution_texture] SMB connections look transaction-templated.** Across `zeek-core/smb_mapping.json` and `zeek-core/smb_files.json`, all 118 tree mappings use different Zeek UIDs; all 118 corresponding connections are `SF`, with a median duration of 2.636 seconds and a maximum of 10.375 seconds. Of 102 UIDs containing file operations, 89 contain exactly two rows—one `SMB::FILE_OPEN` followed by one read or write. A representative Finance burst creates separate TCP sessions for `Q1-forecast.xlsx` at 16:05:30.321746Z, `Q1-budget.xlsx` at 16:05:50.395973Z, and `Q1-variance.xlsx` at 16:06:30.363364Z. Real workstation SMB clients more commonly reuse a transport and tree mapping across adjacent operations. Reconnection-per-file is possible, but its fleet-wide regularity is a synthetic texture.
- **[environment_or_collection_plausibility] Web sensor visibility is sharply source-selective without an evident network explanation.** `WEB-EXT-01.meridianhcs.local/web_access.log` has 852 requests, but only 202 Zeek HTTP records target 10.10.3.10 in `zeek-dmz/http.json`; every Zeek row can be associated with a server access row. Most notably, none of the 397 requests from 185.70.41.45 appear in Zeek HTTP, including the 13:19:37Z upload, while the same sensor records other external and internal clients. A routed or sampled collection design could explain this, so it is not treated as a hard contradiction, but the source-specific exclusion should be documented.
- **[weak_signal] Fleet scheduling is exceptionally regular.** Ten Linux hosts record `/usr/lib/sysstat/debian-sa1` on fixed per-host 30-minute phases. For example, APP-INT-01 has 12 launches with consecutive gaps from 1,799.877 to 1,800.247 seconds, while several other hosts have exactly one 3,600-second gap. Cron or systemd timers can produce this pattern, so it carries little weight by itself.
## Evidence For Real
- Windows audit behavior is source-native rather than merely time-aligned. In `DC-01.meridianhcs.local/windows_event_security.xml`, Event 4688 records `wevtutil cl Security` at 17:42:02.7944174Z with EventRecordID 28261026. Event 1102 follows at 17:42:06.2498202Z with EventRecordID 1, correctly reflecting the Security-channel reset, while `windows_event_sysmon.xml` continues independently.
- The PsExec chain is operationally coherent across endpoint and network sources. DC-01 records a Type 3 NTLM logon for `aisha.johnson` from 10.10.1.35:56233 at 16:00:18.7954996Z. WS-AJOHNSON records outbound TCP/445 at 16:00:29.9519158Z; DC-01 sees the inbound flow at 16:00:30.9114759Z and Sysmon sees it at 16:00:30.9076608Z. DC-01 then records `PSEXESVC.exe` file creation at 16:00:31.630Z, service installation at 16:00:31.9366Z, service-process creation near 16:00:43.5Z, and child `cmd.exe /c whoami && hostname` near 16:00:46.2Z. Child termination at about 16:00:49Z and service termination near 16:01:03Z preserve lifecycle order.
- Account and persistence pivots retain stable identities. DC-01 shows `net user svc_dirsync ... /add /domain` at 16:14:53Z, Security events 4720/4724/4738 between 16:14:57.136Z and 16:14:59.305Z, and group addition Event 4728 at 16:15:01.767Z. The new SID consistently ends in 9101. Service installation at 16:20:07.263Z and task creation at 16:20:09.855Z are followed by the service binary starting under `services.exe` at 16:30:40.621Z.
- Zeek protocol contracts are internally sound. Every DNS, HTTP, and SSL UID examined has a parent `conn.json` row with matching tuple and a timestamp inside the connection interval; all file `conn_uids` resolve. All X.509 chain references resolve, observed certificates fall within their validity windows, and leaf issuer/parent subject relationships agree. The three sensors use independent UIDs and exhibit plausible clock offsets: the 254 ICMP discovery probes appear in core approximately 114.098 ms after DMZ on average, with 0.899 ms standard deviation.
- Traffic texture varies by role and outcome. `zeek-core/conn.json` includes DNS, Kerberos, LDAP, SMB, HTTP, TLS, successful flows, resets, rejects, and 1,488 TCP `S0` records. `zeek-db/conn.json` has 215 successful MySQL flows alongside 26 `RSTO`, 17 `RSTR`, ten `S2`, three `S3`, and two `OTH`. Windows-like hosts use 49152–65535 ephemeral ports while Linux-like hosts predominantly use 32768–60999.
- Windows executable identity varies credibly by operating-system build. Native binaries such as `cmd.exe`, `conhost.exe`, `svchost.exe`, `taskhostw.exe`, and `WmiPrvSE.exe` retain stable hashes within a build and differ across builds 17763, 19041, 20348, and 22621. No MD5/SHA1/SHA256 collision was found across different basenames in the 137 observed hash sets.
- Stateful perimeter logging has realistic window edges. `fw-perimeter/cisco_asa.log` contains 9,308 connection-build messages and 9,306 teardowns. Of 7,281 parsed TCP connection IDs, 7,279 have both sides; the two open-only IDs are SSH connections established at 17:32:54Z and 17:40:04Z that plausibly remain active at the end of the capture.
## Detailed Analysis
The data is highly huntable. A web pivot begins with the 185.70.41.45 upload at 13:19:37Z, reaches Apache-spawned shell activity at 13:19:41.450Z, and produces the 10.10.3.10:49708→45.33.32.30:8443 session in endpoint telemetry at 13:19:45.139Z and Zeek DMZ at 13:19:45.214177Z. The Zeek connection UID `CYnRyimZyjXtzHTAS` is `SF`, lasts 8.926289 seconds, and carries 620 originator bytes and 1,840 responder bytes over 6/7 packets. The outer process ends at 13:20:05.428Z, after the transport closes. The timing is coherent; the defect is process ownership and missing lineage, not event order.

The next major pivot is equally usable. `WS-AJOHNSON-01.meridianhcs.local/ecar.json` records an outbound connection from 10.10.1.35:54741 to 10.10.3.10:22 at 13:40:15.172Z. WEB-EXT-01 creates the privileged `sshd` child at 13:40:16.021Z, reports the inbound flow at 13:40:16.687Z, logs the root session at 13:40:27.561Z, and creates the shell at 13:40:29.388Z. `WEB-EXT-01.meridianhcs.local/syslog.log` independently records connection receipt at 13:40:19.349639Z, accepted password at 13:40:27.877735Z, PAM session open at 13:40:27.962750Z, and logind session creation at 13:40:28.602039Z. This is strong transport-before-auth-before-shell ordering.

The scan defect emerges only after following that valid SSH chain. The operator runs host and resolver discovery, then `find /opt/ehr -name *credential* -maxdepth 3`, then the two Nmap commands. The initial discovery's nine responsive addresses are exactly 10.10.2.10, .11, .20, .21, .25, .26, .27, .30, and .40 in both Zeek sensors. The second command nevertheless yields nearly 5 × 254 TCP attempts. Because the two process records identify separate invocations, the earlier host-discovery result cannot alter the later Nmap process. This is the most probative authenticity failure in the corpus.

The Windows lateral movement and persistence sequence does not contain the common lifecycle failures seen in weak synthetic logs. Logon IDs, PIDs, process parents, source ports, and service identities remain stable across Security, Sysmon, eCAR, Zeek, and ASA where those sources have visibility. Minor inter-source timestamp differences are directionally plausible. No eCAR file had a timestamp inversion or duplicate event ID, no observed process termination preceded its visible creation, and no checked dependent event referenced a process created later.

Background volume is substantial and role-sensitive rather than uniformly distributed. DC-01 alone has 6,430 Security and 4,301 Sysmon events; DC-02 has 5,649 and 3,579. Zeek core contains 11,102 connections, DMZ 8,226, and DB 441. Proxy and web tiers dominate expected HTTP volumes, while database and workstation hosts are materially quieter. DHCP consists of 48 `REQUEST`/`ACK` renewal records from six clients, with lease intervals of 3,600, 7,200, or 14,400 seconds and renewal timing near T/2. These distributions and the presence of benign suspicious DNS, Internet scanning, resets, partial source visibility, and source-local timing differences argue against a simplistic handcrafted trace.

Signal-to-noise is therefore credible, and the compromise is pivotable without relying on a single source. The verdict changes only because the Nmap footprint violates the visible tool contract and is accompanied by two lower-severity construction patterns. The absence of broad schema defects and the strength of the remaining telemetry keep the score below the confidently-synthetic 81–100 range.
## Synthetic Indicator Summary
- **hard_contradiction — High:** A non-`-Pn` Nmap connect scan touches almost all five ports on all 254 subnet addresses after only nine hosts respond to discovery.
- **contract_gap — Medium:** The reverse-shell pipeline omits `base64` and nested Bash children and attributes the TCP socket to the outer pipeline shell.
- **distribution_texture — Medium:** All 118 SMB mappings create unique, short-lived successful connections; 89 of 102 file-bearing connections contain exactly an open plus one transfer operation.
- **environment_or_collection_plausibility — Low:** Zeek DMZ contains only 202 of 852 server-visible HTTP requests and excludes all 397 requests from one high-volume source despite observing other external clients.
- **weak_signal — Low:** Linux sysstat launches have fleet-wide fixed 30-minute phases with subsecond jitter and isolated single skipped intervals.
- **schema_or_format — No material defect:** XML, JSON, RFC 5424-like syslog, Zeek, Snort, web/proxy, and ASA records are syntactically and field-semantically strong.
## Realism Score by Category
- **Field format accuracy:** 9 — Source-native schemas, Windows record semantics, Zeek protocol fields, ASA lifecycles, hashes, SIDs, PIDs, and Logon IDs are consistently plausible; no material formatting defect was found.
- **Temporal patterns:** 8 — Attack and baseline lifecycles are ordered correctly with believable source latency and clock skew, although fleet timers and short SMB sessions are overly regular.
- **Cross-source correlation:** 9 — Network tuples, process identities, authentication state, files, services, and protocol companions support reliable pivots without timestamp inversions; selective HTTP visibility needs explanation.
- **Behavioral realism:** 5 — Most tradecraft is operationally credible, but the Nmap footprint contradicts the command and the reverse-shell process tree is incomplete at the point where execution semantics matter most.
- **Environmental consistency:** 8 — Host roles, traffic volumes, OS-specific port ranges, DHCP renewal behavior, Internet noise, and server/workstation activity are differentiated and coherent; SMB sessionization is too uniformly transactional.
## Recommendations
1. Preserve Nmap stdout/stderr, packet capture, and `/etc/nmap/nmap.conf` for the 13:40–13:42Z interval. If no global option supplied `-Pn`, treat the five-port sweep of all 254 addresses as a confirmed authenticity failure. Model the second invocation's own discovery probes and restrict service scanning to hosts it classifies as up.
2. Retain full exec/process ancestry for shell pipelines. The 13:19:41Z chain should expose `/usr/bin/base64`, the consuming child Bash, and the process that actually opens 45.33.32.30:8443, with separate start/exit records where the endpoint source claims process visibility.
3. Reproduce SMB behavior from client packet captures or endpoint SMB telemetry. Reuse TCP sessions and tree mappings across adjacent file operations, and include longer idle/persistent mappings, multiplexed file access, reconnects, authentication failures, and occasional incomplete sessions instead of predominantly one-file successful transactions.
4. Document the Zeek DMZ collection boundary, sampling policy, and source-level exclusions. If 185.70.41.45 traverses the same monitored path as the external clients that appear in `http.json`, the 0-of-397 HTTP visibility requires correction or an explicit loss mechanism visible elsewhere.
5. Keep the strong native behaviors already present: Windows channel-reset semantics, role-specific baseline volume, build-specific hashes, independent sensor UIDs and clock offsets, bounded-window open connections, and source-local observation gaps. These features materially improve hunt realism and should remain independent of attack-story completeness.
