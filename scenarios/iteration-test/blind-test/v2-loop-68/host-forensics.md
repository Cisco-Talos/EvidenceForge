# Host/EDR Forensics Analyst — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 96
**Synthetic-Confidence Score:** 92
## Executive Summary
The endpoint corpus is highly polished at the Windows Security/Sysmon/eCAR correlation layer, but it contains a repeated Linux process/session contradiction that is not credible as ordinary production telemetry. Across 11 Linux hosts, 71 `sudo` records map to 14 unchanged parent `/bin/bash` PIDs while the recorded terminal changes among two to four `pts/*` devices. A running shell process does not migrate repeatedly between controlling terminals in this fashion, and the eCAR records identify each `sudo` process as a direct child of the same shell process and process UUID. This is a fleet-wide hard contradiction and the primary basis for the verdict.

A second, independent defect affects SSH lifecycle integrity: eight `sshd` PIDs on five hosts are created by eCAR during the six-hour observation window, but syslog contains only a session-close record for each PID, with no same-PID connection, authentication, PAM-open, or session-open record. That asymmetry is inconsistent with the otherwise detailed SSH collection profile and is more specific than generic thin coverage.

The strongest counterweight is the Windows evidence. Process starts, terminations, logons, account changes, service creation, file activity, and network events are temporally ordered and source-native. Of 965 Windows Sysmon Event ID 1 process starts, 964 have a matching Security 4688 record with matching host, PID, and image; visible parent lifetimes and logon identifiers are also internally coherent. These strengths materially improve realism, but they do not explain the repeated Linux terminal impossibility.

## Evidence For Synthetic
- **[hard_contradiction] A single shell process repeatedly changes terminal identity.** In `APP-INT-01.meridianhcs.local/ecar.json`, `sudo` PIDs 2940058, 2940071, 2940081, and 2940133 are all direct children of `/bin/bash` PID 2931384 and actor UUID `e8507789-17ce-4d86-8471-1216cc860162`. Yet `APP-INT-01.meridianhcs.local/syslog.log` records those invocations at 12:49:24.515754, 12:49:31.724969, 12:49:36.197867, and 12:50:02.448263 UTC on `pts/0`, `pts/5`, `pts/2`, and `pts/3`, respectively. The same parent remains the direct caller; no intervening shell replacement or session transition is represented.
- **[hard_contradiction] The terminal defect is systematic rather than isolated.** The same pattern covers 71 `sudo` records, 14 parent shell PIDs, and 11 hosts. Examples include DB-PROD-01 shell PID 1043863 across `pts/2,3,4,6` (`syslog.log` lines 6-53), LOG-MON-01 PID 685352 across `pts/3,4,10` (lines 1-51), PROXY-01 PID 2369184 across `pts/0,1,3,5` (lines 4-49), WEB-EXT-01 PID 2695277 across `pts/4,6,8,9` (lines 36-92), and WS-OHADDAD-01 PID 4056734 across `pts/0,1,3,5` (lines 94-181). Reuse across different sessions would require different shell processes or identities; neither occurs in these chains.
- **[contract_gap] Eight in-window SSH processes have close-only syslog lifecycles.** For example, `APP-INT-01.meridianhcs.local/ecar.json` line 371 creates `sshd` PID 2974176 at 15:49:38.486 UTC, while `syslog.log` line 171 contains only `pam_unix(sshd:session): session closed for user marcus.chen` at 16:22:24.578624 for that PID. PID 2984052 is created at 17:16:18.179 (`ecar.json` line 709) and has only a root close at 17:16:46.071392 (`syslog.log` line 202). Comparable orphan closes occur for PID 689842 on LOG-MON-01, PIDs 460744 and 503370 on MAIL-CLIN-01, PID 1987712 on MAIL-EDGE-01, and PIDs 2698441 and 2707520 on WEB-EXT-01. Because the process itself starts inside the observed interval, these are not sessions inherited from before collection began.
- **[distribution_texture] Linux service chatter is unusually repetitive and fleet-wide.** The 11 syslog files contain 507 `irqbalance` and 466 `snapd` records in six hours. APP-INT-01 alone records 43 `irqbalance` and 48 `snapd` messages; WEB-EXT-01 records 97 and 104. Examples include `NUMA node 0: balancing pass complete, 2 IRQs moved` at 12:03:14.498946, `IRQ 24 affinity hint keeps vector on CPU 1 (ens160)` at 12:09:34.030672, and `Skipping IRQ 24: banned by affinity mask 00000001 (ens160)` at 12:20:18.606624 in `APP-INT-01.meridianhcs.local/syslog.log`. Such high-rate diagnostic-style text can exist under deliberate verbose logging, but its broad, similarly textured deployment across servers and workstations is atypical.
- **[environment_or_collection_plausibility] The SSH omissions are selectively one-sided despite detailed collection elsewhere.** Other SSH PIDs in the same files carry connection, accepted-key/password, PAM-open, systemd-logind, and close records with stable user keys and plausible ordering. Repeatedly retaining only the terminal close for newly created session processes is difficult to reconcile with a stable source-local collection policy.

## Evidence For Real
- Windows event formatting and sequencing are strong. Across ten Windows hosts, 964 of 965 Sysmon Event ID 1 records have a matching Security 4688 process creation by host, PID, and image. Matching Security events generally follow Sysmon by approximately 35-647 ms, a plausible sensor-specific delay rather than an identical timestamp copy.
- No terminate-before-create, logout-before-login, or overlapping PID-reuse condition was found in the endpoint records. A focused Windows parent-lifetime check covered 246 child processes whose parents were visible in-window and found zero children created after parent termination.
- Security 4624 logon identifiers and GUIDs agree with Sysmon process `LogonId`/`LogonGuid` values where both are visible. Repeated identifiers such as `0x3e4`, `0x3e5`, and `0x3e7` are appropriately associated with built-in Windows identities rather than arbitrary user sessions.
- The credential-access chain on WS-AJOHNSON-01 is source-native and tightly ordered. `ecar.json` records PID 6316 (`ms-index-service.exe`) at 15:45:22.312 UTC with command arguments `privilege::debug` and `sekurlsa::logonpasswords`, parent PowerShell PID 6220, and logon ID `0x27002b1`. Sysmon Event ID 1 occurs at 15:45:22.2518097, Security 4688 at 15:45:22.3259498, Sysmon Event ID 10 accesses `winlogon.exe` and `lsass.exe` at 15:45:25.776 and 15:45:34.009, Event ID 8 follows at 15:45:34.121, and Event ID 5 plus Security 4689 close the process at 15:45:34.130 and 15:45:34.185.
- DC-01 preserves a credible multi-source administrative lifecycle: eCAR service creation for `PSEXESVC` occurs at 16:00:31.871 and Security 4697 at 16:00:31.936; account creation/change/group-add events 4720, 4724, 4738, and 4728 occur from 16:14:57.136 through 16:15:01.767 after matching `net.exe` process activity; service/task events 4697 and 4698 follow their `sc.exe` and `schtasks.exe` processes; and `wevtutil cl Security` at 17:42:02 precedes Security 1102 at 17:42:06. The subsequent Security event record ID restart at 1 is consistent with a cleared channel.
- User activity is differentiated rather than cloned. The 22 bash-history files contain 312 commands and 235 unique commands. There are no duplicated three-command sequences and only two duplicated two-command sequences, both operationally ordinary. Inter-command timing has 192 unique gap values among 292 gaps. Histories also differ by role and user; for example, APP-INT-01 root history is empty after a visible 17:41:18 `history -c` command, while DB-PROD-01 root retains staging and `scp` activity.
- Linux SSH details that are present are generally credible: user-to-key fingerprints remain stable across hosts, accepted-authentication records precede PAM/session records, and session closure timing is not mechanically identical to transport timing.

## Detailed Analysis
The decisive issue is process identity, not narrative neatness. The eCAR records provide both numeric parent PID and durable actor UUID for Linux process creation. Within each affected chain, multiple `/usr/bin/sudo` instances name the same living `/bin/bash` as direct parent. Syslog then assigns those child invocations different `TTY=pts/N` values. A terminal may differ between independent login sessions, and a PID may eventually be reused, but neither explanation fits a single continuous shell object directly spawning commands seconds apart. On APP-INT-01, four terminal identities occur within 38 seconds. On DB-PROD-01 and MAIL-EDGE-01, two separate shell trees on each host independently exhibit the same defect. The breadth and repetition make parser corruption or one damaged host implausible.

The SSH defect is weaker but independent. The corpus visibly records rich SSH lifecycle detail for many sessions, making complete omission of all opening evidence for exactly eight newly created `sshd` session PIDs a source-local lifecycle gap. The affected durations range from roughly 28 seconds to more than 55 minutes, and the issue spans root, aisha.johnson, and marcus.chen. A lossy collector could drop individual records, but repeatedly preserving only close records for these new processes while surrounding sessions are complete is a conspicuous asymmetry.

Windows process trees do not show a comparable structural failure. Service parents, PowerShell descendants, WMI-launched commands, `net.exe`/`net1.exe`, archive staging, and `curl.exe` network activity remain inside visible parent and logon lifetimes. WS-AJOHNSON-01 also maintains a Type 9 credential context: Security 4624 at 17:00:41 identifies Aisha Johnson as the target session and Marcus Chen as outbound identity under logon ID `0x27c97b5`; subsequent staging activity uses that logon context. Although some parent choices are uncommon, the records do not establish an impossible Windows state.

Host-role details are also consistent. DC-01 and DC-02 system binaries predominantly report Windows Server build `10.0.20348.1`. No SHA-256 value was observed reused for the same image name with conflicting file versions across the Windows hosts. Linux user IDs and SSH key fingerprints remain stable for recurring users. These controls argue against a low-quality fabrication and explain the high scores for field accuracy and correlation.

The verbose `irqbalance`/`snapd` population is not independently dispositive. RFC 5424 formatting is valid, and an intentionally broad `daemon.info` collection profile could retain these records. Its evidentiary value comes from the volume and repetitive fleet-wide texture, not from an invalid field or impossible message. It therefore receives substantially less weight than the terminal contradiction.

## Realism Score by Category
- **Field format accuracy:** 9 — Security, Sysmon, RFC 5424 syslog, bash-history, and eCAR fields are well formed and largely source-native; no broad schema corruption was found.
- **Temporal patterns:** 7 — Windows process/logon/service timing is strong and no lifecycle inversions were found, but close-only SSH sessions weaken source-local temporal completeness.
- **Cross-source correlation:** 9 — Windows PID, image, logon, service, file, and network relationships align exceptionally well; 964/965 Sysmon process starts match Security 4688.
- **Behavioral realism:** 4 — User differentiation and process trees are convincing, but a single shell repeatedly changing among multiple terminals is a fundamental behavioral impossibility.
- **Environmental consistency:** 6 — Host roles, OS builds, users, keys, and account lifecycles are coherent; fleet-wide diagnostic daemon texture and selective SSH gaps reduce plausibility.

## Recommendations
- Treat the shell/TTY relationship as immutable session state. Every child of a continuing interactive shell should inherit that shell's terminal unless a separately evidenced session and shell process is created.
- Validate endpoint lifecycles as source-local groups. If an SSH session's close record is retained, preserve or intentionally account for its connection, authentication, PAM-open/session-open, and process-start companions under the same PID.
- Reassess the Linux daemon collection profile. Either document a fleet-wide verbose `irqbalance`/`snapd` configuration or reduce diagnostic message frequency and make host-specific enablement reflect server role and operating state.
- Preserve the existing Windows correlation quality, especially the small source-specific timestamp offsets, logon GUID/LUID continuity, parent lifetimes, and Security event-record reset after channel clear.
- Add an authenticity gate that checks invariant host semantics—not merely matching fields—including controlling-terminal stability, parent-process lifetime, session open/close balance, and process identity continuity across source views.
