# Host/EDR Forensics Analyst — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 92
**Synthetic-Confidence Score:** 86

## Executive Summary
The reviewed telemetry is highly polished and often convincing at the individual-record and cross-source levels, but several repeated record-visible defects are inconsistent with organically collected production endpoint data. The strongest finding is a fleet-wide contradiction in Windows core-binary metadata: hosts showing Windows Server build 17763, Server build 20348, and workstation build 22621 components all execute an identical `explorer.exe` identified as version 10.0.19041.1 with the same SHA-256. On individual hosts, `winlogon.exe` and `userinit.exe` identify one Windows build while the immediately launched shell identifies another. This is a hard environmental contradiction repeated across unrelated systems.

The second major finding is a systematic SSH lifecycle defect. In 32 of 39 measurable SSH sessions, the recorded login shell terminates more than 60 seconds before PAM/eCAR session closure; 23 gaps exceed five minutes and 12 exceed fifteen minutes. No eCAR process in the same logon session survives across any of those 32 gaps. That pattern is inconsistent with an interactive SSH channel whose session lifetime is governed by its login shell, unless an unrecorded session-owning process repeatedly replaces it. The same unexplained structure across many hosts makes a collection-only explanation unlikely.

Two additional population-level fingerprints reinforce the conclusion: all 19 visible RDP Type 10 session startups place `explorer.exe` only 148–152 milliseconds after `userinit.exe`, and 691 of 938 Sysmon process-create records omit all five PE metadata fields, including every observed creation of several standard Microsoft binaries. These are systematic rather than isolated defects. Conversely, process GUID/PID lifecycles, Security logon pairing, source-native event ordering, user placement, attack sequences, and cross-source identifiers are unusually strong. On balance, the dataset is confidently synthetic but generated with substantial endpoint-domain knowledge.

## Evidence For Synthetic
1. **Incompatible Windows core-binary build metadata on the same systems — `hard_contradiction`.** In `DC-01.corp.local/windows_event_sysmon.xml`, `winlogon.exe` at `2024-03-18T12:48:34.4902021Z` and `userinit.exe` at `12:48:35.8400459Z` report FileVersion `10.0.20348.1`, while the shell they launch at `12:48:35.9902837Z`, `C:\Windows\explorer.exe`, reports `10.0.19041.1`. The same host later identifies PowerShell as `10.0.20348.1` at `13:01:40.5643762Z`. `DC-02.corp.local` and `MAIL-FIN-01.corp.local` repeat the 20348-versus-19041 mismatch; `FILE-SRV-01.corp.local` reports 17763 for `winlogon.exe`/`userinit.exe` but 19041 for `explorer.exe`; and `WS-PPATEL.corp.local` reports 22621 for `winlogon.exe`, `userinit.exe`, and PowerShell but 19041 for `explorer.exe`. This is not merely a mixed fleet: mutually incompatible core-component build identities occur within the same booted host and session.

2. **One identical shell binary is reused across incompatible OS families — `hard_contradiction`.** Eight hosts spanning the above server and workstation build families report `explorer.exe` as FileVersion `10.0.19041.1` with exactly SHA-256 `EA980949D49A837FB13FD9306217AB3A52A384685EB710C9135AE9EDF011FEB5`. The affected hosts are `DC-01`, `DC-02`, `FILE-SRV-01`, `MAIL-FIN-01`, `WS-AJOHNSON`, `WS-DRAMIREZ`, `WS-PPATEL`, and `WS-SMARTINEZ`. An unsupported manual transplant of one shell binary could theoretically explain one machine, but its exact repetition across domain controllers, servers, and workstations with different core builds is not a plausible production state. The observed pattern is consistent with metadata selected from a path-based catalog instead of extracted from each host's actual PE image.

3. **SSH login shells routinely terminate long before their sessions close — `contract_gap`.** Of 39 SSH sessions containing both a `-bash` lifecycle and logout, the median interval from shell termination to logout is 498.973 seconds. Thirty-two exceed 60 seconds, 23 exceed 300 seconds, 12 exceed 900 seconds, and the maximum is 1,669.379 seconds. In every one of the 32 gaps over 60 seconds, no other eCAR process with the same `logon_id` remains alive across the gap. For example, `PROXY-01.corp.local/ecar.json` records logon `0x107aa499` at `2024-03-18T15:17:46.841Z`, `-bash` creation at `15:17:47.947Z`, shell termination at `15:45:37.050Z`, and logout at `16:13:26.429Z`. `PROXY-01.corp.local/syslog.log` independently places PAM close at `16:13:26.990170Z` and systemd session removal at `16:13:27.417897Z`. Thus the endpoint shell disappears 27 minutes 49 seconds before both sources close the session, without a recorded replacement or surviving child.

4. **The same SSH defect appears in a security-relevant session — `contract_gap`.** In `DB-PROD-01.corp.local/ecar.json`, root logon `0x1185eba9` begins at `2024-03-18T17:14:58.918Z`; its `-bash` starts at `17:15:00.561Z` and terminates at `17:35:01.098Z`, but logout is delayed until `17:54:06.710Z`, a gap of 1,145.612 seconds. `DB-PROD-01.corp.local/syslog.log` corroborates authentication at `17:14:58.752165Z`, PAM open at `17:14:58.821884Z`, PAM close at `17:54:06.451768Z`, and systemd removal at `17:54:06.765489Z`. The transfer processes finish much earlier and no same-session eCAR process bridges the shell-to-logout interval. A single orphan could reflect lost telemetry; the recurring fleet-wide distribution indicates a lifecycle-model defect.

5. **RDP shell startup has an unnaturally narrow deterministic delay — `distribution_texture`.** All 19 visible successful Type 10 sessions place `explorer.exe` 148–152 milliseconds after `userinit.exe`: nine delays are exactly 150 ms, seven are 151 ms, and only one each is 148, 149, or 152 ms. This five-millisecond range persists across `DC-01`, `DC-02`, `FILE-SRV-01`, `MAIL-FIN-01`, and `WS-AJOHNSON`, despite different users, roles, and host loads. `DC-01.corp.local/windows_event_sysmon.xml`, for example, records `userinit.exe` at `12:48:35.8400459Z` and `explorer.exe` at `12:48:35.9902837Z`, a 150.238 ms gap. Production RDP startup includes profile loading, policy processing, registry access, service contention, and desktop initialization; it should not collapse to this almost invariant cross-host interval.

6. **Sysmon process-create PE metadata is populated by a selective finite profile — `schema_or_format`.** Of 938 Sysmon Event ID 1 records, 691 (73.7%) set all of `FileVersion`, `Description`, `Product`, `Company`, and `OriginalFileName` to `-`, affecting 54 distinct image paths. This includes every observed creation of `taskhostw.exe` (142/142), `WmiPrvSE.exe` (111/111), `dllhost.exe` (96/96), `conhost.exe` (93/93), `SearchFilterHost.exe` (27/27), `SearchProtocolHost.exe` (26/26), `svchost.exe` (24/24), and `cmd.exe` (23/23). Other Microsoft images such as `winlogon.exe`, `userinit.exe`, `explorer.exe`, and PowerShell consistently receive rich metadata. The all-or-none image-specific pattern across the fleet is inconsistent with ordinary live PE metadata extraction and resembles a partially populated executable catalog.

7. **Process-access records show limited source-native texture — `weak_signal`.** The 738 Sysmon Event ID 10 records use only eight normalized call-trace module-chain shapes and seven GrantedAccess values; 293 use `0x1000`, 144 use `0x1400`, and 115 use `0x1010`. Filtering policy and common Windows access paths can naturally constrain this field, so this is not decisive. It modestly reinforces the stronger evidence because the same small vocabulary recurs across a relatively large event population.

## Evidence For Real
- The XML sources are structurally sound. All Windows Security and Sysmon documents parsed successfully, and provider, channel, event version, task, opcode, keyword, and event-data forms are internally coherent. Sysmon `UtcTime` values are plausibly slightly earlier than the enclosing event-system timestamps rather than being mechanically identical.

- Timestamp and record-sequence discipline is strong. No source file contains a backward timestamp transition, and Windows `EventRecordID` values are monotonic without duplicate IDs. `DC-01.corp.local/windows_event_security.xml` records Event ID 1102 at `2024-03-18T17:42:01.2672792Z`, correctly resets the Security record sequence, and then continues from the new sequence while Sysmon remains unaffected. The clear event also contains credible SYSTEM subject fields (`NT AUTHORITY`, Logon ID `0x3e7`).

- Sysmon process lifecycles are internally consistent. Across 760 visibly paired process create/terminate lifecycles, there are no negative durations, no dependent Sysmon events before the matching process creation, no dependent events after its termination, and no parent process that is created after its child. There are no process GUIDs assigned multiple PIDs and no image path that changes hash within a host.

- eCAR object identity is exceptionally coherent. Across all 21 host directories, no dependent event references an actor before its process creation, no event references an actor after its termination, no process object has duplicate lifecycle creation, and no PID reuse overlaps a live process. All 5,445 checked `actorID`/`source_process_uuid` relationships agree, all 738 checked process-open `objectID`/`target_process_uuid` relationships agree, and all 2,770 applicable PID/source-PID relationships agree.

- Windows session records retain credible semantics. Security Event IDs 4624 and 4634 show no visible logout-before-login pair. SID-to-account mappings are globally stable: no sampled user maps to multiple SIDs and no SID maps to multiple users. Reuse of a logon ID for Type 2 and Type 7 activity on `WS-DRAMIREZ` and `WS-PPATEL` is consistent with workstation lock/unlock behavior rather than an error.

- Native SSH event ordering is credible even though session termination is not. In 43 complete syslog SSH sessions, none has acceptance before connection, PAM open before acceptance, or PAM close before open. Acceptance-to-PAM-open delays span 45–180 ms with 43 distinct observed values. `APP-INT-01.corp.local/syslog.log`, for example, records connection at `2024-03-18T12:02:04.504467Z`, acceptance at `12:02:10.030893Z`, PAM open at `12:02:10.112277Z`, and systemd session creation at approximately `12:02:10.582Z`. eCAR login-to-shell delays also vary broadly from 233 to 2,566 ms, with 42 distinct values among 43 sessions.

- User and host-role diversity is convincing. Primary users dominate their assigned workstations, with human identities including aisha, marcus, lina, priya, diego, omar, evelyn, and sophia alongside service identities. Linux UIDs remain stable across sources—for example, aisha uses UID 2528, marcus 4119, and lina 5302. Bash histories use native `#<epoch>` timestamp lines, contain varied role-appropriate commands, and align with corresponding eCAR process times.

- Security-relevant causal chains are detailed and correctly ordered. On `WS-AJOHNSON`, the process masquerading as `ms-index-service.exe` begins at `2024-03-18T15:45:12.5900723Z` with a `sekurlsa::logonpasswords` command line, followed by Sysmon process-access events targeting winlogon and LSASS and a remote-thread event before termination at approximately `15:45:18Z`. On `DC-01`, account-management, service-installation, scheduled-task, and log-clear activity occurs in plausible process-to-Security order between `16:15Z` and `17:50Z`.

- The `DB-PROD-01` transfer has strong endpoint causality. `ecar.json` records `mysqldump` creation at `2024-03-18T17:15:02.736Z`, creation of `/tmp/rpt_0318.sql` at `17:15:03.985Z`, dump termination at `17:15:18.138Z`, `gzip` creation at `17:15:19.580Z`, compressed-file creation at `17:15:23.528Z`, `scp` creation at `17:15:39.661Z`, a flow to `10.10.2.30:22` at `17:15:43.026Z`, file read at `17:15:49.450Z`, and target-side file creation on `APP-INT-01` at `17:15:55.530Z`. This is a realistic causal ordering and is not counted as synthetic merely because it correlates well.

## Detailed Analysis
The corpus contains 125,889 records across the available source files: 33,946 eCAR records, 18,529 Windows Security events, 11,690 Sysmon events, 3,750 Linux syslog lines, and 350 bash-history commands, plus network-facing Zeek, firewall, proxy, web, and Snort data. Endpoint telemetry covers ten Windows systems with Security/Sysmon/eCAR and eleven Linux systems with eCAR plus varying syslog/bash visibility. The principal time window is approximately `2024-03-18T12:00:00Z` through `18:00:00Z`.

At the record level, the Windows data is substantially better than simplistic fabricated telemetry. Process IDs, process GUIDs, parentage, logon IDs, SIDs, hashes, and event-record counters remain stable. Process creation, access, network, DNS, and termination events appear in lawful local order. The lack of lifecycle inversions is meaningful evidence for realism, though not dispositive: deterministic generation can enforce the same invariants.

The Windows build evidence is qualitatively different because it is not a matter of tidy correlation or incomplete collection. FileVersion and hash fields claim facts about binaries that cannot all describe the installed operating systems shown by adjacent core executables. The repeated `explorer.exe` identity across 17763-, 19041-, 20348-, and 22621-family systems is the clearest authenticity failure in the host evidence. It receives greater weight than fields that are merely missing.

The PE metadata omissions are likewise evaluated as a population pattern, not as a complaint that Sysmon must always emit every field. A few inaccessible, packed, or unsigned binaries can legitimately lack version resources. Here, however, hundreds of standard Microsoft images lose exactly the same five fields on every creation while a limited group receives complete, reusable metadata. Hashing remains present in 913 of 938 process creates, so a broad process-read failure does not explain the metadata split. Twenty-five process creates lack hashes as well, including the suspicious `ms-index-service.exe` record at `2024-03-18T15:45:12.5900723Z` and two `curl.exe` starts on that host at `17:24:44.547Z` and `17:24:44.958Z`; missing hashes alone would be weak evidence, but the broader per-image metadata partition is not.

Session behavior is mixed. Authentication and session-open ordering is source-native and varied, and Windows logon/logoff semantics do not show obvious inversions. However, RDP desktop initialization is nearly constant to the millisecond across every observed server and workstation. More importantly, Linux session ownership breaks after the shell exits. A telemetry-loss hypothesis would require eCAR to omit every replacement/background process while still capturing the shell termination and much later logout, and for that selective gap to recur in 32 sessions across multiple systems. The synchronized syslog/eCAR close times show that the late close is intentional data, not a timestamp parsing artifact.

Behavioral composition is otherwise strong. Workstation users, service identities, administrative activity, Linux command histories, file operations, credential access, persistence, account management, and transfer chains have plausible host placement and causal order. The six-hour slice also contains substantial baseline traffic and process noise rather than only attack actions. Those strengths lower confidence that the data is a crude fixture, but they do not resolve the hard binary-state contradiction or repeated lifecycle contracts.

Collection plausibility is generally good: sources differ in volume and visibility, and missing event classes were not treated as suspicious. The assessment does not rely on absent Sysmon types, sanitized names, external DNS behavior, filesystem timestamps, thin coverage, narrative neatness, or the mere fact that sources correlate. It relies on values and distributions present in the logs themselves.

## Realism Score by Category
- **Field format accuracy:** 7 — Native XML, eCAR, syslog, and bash formats are largely coherent, but the systematic PE metadata omissions and incompatible Windows core-file versions materially reduce accuracy.
- **Temporal patterns:** 5 — Baseline and authentication timings show useful variation, while the 148–152 ms RDP startup band and repeated long shell-to-session-close gaps expose deterministic timing/lifecycle construction.
- **Cross-source correlation:** 9 — Process, session, file, network, and identity relationships are unusually consistent, with no observed ordering failures in thousands of checked references. This score reflects quality, not an inference that correlation itself proves authenticity.
- **Behavioral realism:** 7 — User placement, command diversity, process trees, attack chains, and routine activity are convincing; the recurring SSH ownership gap prevents a higher score.
- **Environmental consistency:** 4 — Stable users, SIDs, UIDs, and host roles are positives, but the cross-build `explorer.exe` contradiction is a fundamental fleet-state failure.

## Recommendations
- Derive PE version resources and hashes from one host-specific installed-image identity. Do not assign metadata solely by executable basename or path. Enforce that Windows core binaries on a host belong to a compatible OS build family.
- Make SSH logout/PAM-close timing contingent on termination of the login shell and any process that actually keeps the session channel alive. If background processes extend the session, emit and retain those process lifecycles under the same logon identity.
- Replace the fixed RDP `userinit.exe`→`explorer.exe` delay with a host-, user-, and session-conditioned distribution that reflects profile state, group policy, server load, and first-versus-repeat login effects.
- Populate Sysmon PE metadata from executable-specific version resources, including common Windows binaries. When metadata is unavailable, vary the cause and field combination instead of assigning the same five-field null profile to every occurrence of an image.
- Expand ProcessAccess call-trace and access-mask texture using caller/target/version-specific behavior, while preserving the already strong GUID, PID, session, and temporal invariants.
- Retain the existing strengths: source-native timestamp offsets, monotonic record state, coherent Security/Sysmon/eCAR identities, realistic bash-history formatting, and causal process/file/network sequencing.
