# Detection Engineer — Authenticity Assessment
## Verdict
**Assessment:** Synthetic
**Verdict Confidence:** 94
**Synthetic-Confidence Score:** 92

## Executive Summary

The telemetry is highly polished and mostly source-native, but several record-visible defects are difficult to reconcile with production collection. The most decisive is a cross-host Windows binary identity contradiction: `C:\Windows\explorer.exe` is reported with the same version and all four hashes on systems whose immediately adjacent Windows components identify Server 2019, Server 2022, Windows 10, and Windows 11 build families. This is reinforced by repeated timing templates: 19 of 24 observed `winlogon.exe` → `userinit.exe` → `explorer.exe` chains fall into a very narrow 1.34–1.36 second and 0.14–0.16 second cadence, while eight failed-SSH sequences preserve exactly the same final three microsecond digits across all events in each sequence because every offset is an integer number of milliseconds.

There is also unusually constrained termination telemetry: all 803 Security Event ID 4689 records have `Status=0x0` across 75 process images. Sysmon hashing is selectively absent for 25 of 938 process creations even though the same collection supplies SHA1, MD5, SHA256, and IMPHASH for the other 913; the omissions include resident Microsoft binaries such as `runas.exe` and `curl.exe` as well as conspicuous service/payload binaries. These are concrete distribution and collection-contract defects, not judgments based on narrative neatness.

Conversely, the dataset gets many difficult details right. All inspected XML and JSON parsed; Windows event versions, tasks, localized tokens, hexadecimal IDs, PIDs, parent identities, and process GUID lifecycles were coherent. All checked Zeek protocol records mapped to a same-sensor `conn.json` UID with matching tuples and valid in-connection timing. ASA connection lifecycles, Kerberos fields, certificate chains, DHCP renewal jitter, and log-clear record-ID reset behavior were also convincing. Those strengths raise field and correlation scores, but they do not explain the binary-identity contradiction or the repeated sub-millisecond timing construction.

## Evidence For Synthetic

- **`hard_contradiction` — OS-bound `explorer.exe` identity is reused across incompatible Windows build families.** In `DC-01.meridianhcs.local/windows_event_sysmon.xml`, EventRecordID 3289539 at `2024-03-18T12:48:35.8400459Z` reports `userinit.exe` version `10.0.20348.1`, while its child `explorer.exe`, EventRecordID 3289540 at `12:48:35.9902837Z`, reports version `10.0.19041.1` and SHA1 `59C3A52B...49FDD`. In `FILE-SRV-01.../windows_event_sysmon.xml`, EventRecordIDs 1644281–1644282 at `12:03:11.9834380Z` and `12:03:12.2243767Z` pair `userinit.exe` version `10.0.17763.1` with that same `explorer.exe` version and SHA1. In `WS-PPATEL-01.../windows_event_sysmon.xml`, EventRecordIDs 739913–739914 at `14:18:21.6898158Z` and `14:18:21.9216418Z` pair `userinit.exe` version `10.0.22621.1` with the same Explorer identity. All 24 Explorer creations use version `10.0.19041.1` and the identical SHA1, MD5, SHA256, and IMPHASH across these host families. An OS component cannot simultaneously be the same binary on those mutually different system builds while neighboring OS components correctly change version and hash.

- **`distribution_texture` — logon process timing is strongly template-constrained.** Of 24 complete Sysmon parent-GUID chains from `winlogon.exe` to `userinit.exe` to `explorer.exe`, 19 have the first delay within 1.34–1.36 seconds and the second within 0.14–0.16 seconds. Examples include DC-01 EventRecordIDs 3289538–3289540 (`1.349843 s`, then `0.150238 s`), DC-02 EventRecordIDs 1372070–1372072 (`1.350099 s`, then `0.149702 s`), and MAIL-FIN-01 EventRecordIDs 781754/781756/781757 (`1.350045 s`, then `0.151014 s`). The same narrow cadence recurring across domain controllers, member servers, mail infrastructure, and workstations is not credible natural scheduler/load variation.

- **`distribution_texture` — failed-SSH lifecycle timestamps reveal integer-millisecond construction.** Eight independent multi-line SSH failure groups preserve the exact same microsecond remainder modulo 1,000 for every event in the group, although normal SSH sessions and other syslog records on the same hosts vary at full microsecond precision. In `APP-INT-01.../syslog.log` lines 107–110, PID 2946355 runs at offsets `0`, `189`, `822`, and `962 ms`, with every timestamp ending in microseconds `570`. In `FILE-LNX-01.../syslog.log` lines 137–140, PID 2700939 uses `0`, `125`, `425`, and `506 ms`, all ending `549`; in `LOG-MON-01.../syslog.log` lines 106–109, PID 705197 uses `0`, `58`, `689`, and `834 ms`, all ending `808`. Five more groups show the same construction on DB-PROD-01, LT-MRIVERA-02, MAIL-EDGE-01, PROXY-01, and WEB-EXT-01. Because the same hosts show non-quantized microseconds elsewhere, this is not a host clock-resolution artifact.

- **`distribution_texture` — every audited Windows process termination is successful.** Across 803 Security Event ID 4689 records covering 75 process images, `Status` is `0x0` without a single nonzero exit. The population includes interactive tools, update utilities, shells, PowerShell, `curl.exe`, `net.exe`, `mstsc.exe`, `MpCmdRun.exe`, service processes, and short-lived host utilities. Zero variation over this volume is implausible for a six-hour, multi-host production slice, even though any individual zero exit status is valid.

- **`contract_gap` — Sysmon hashing is selectively absent under an otherwise four-algorithm policy.** Of 938 Sysmon Event ID 1 records, 913 contain SHA1, MD5, SHA256, and IMPHASH, but 25 use the literal `Hashes=-`. The omissions are not limited to ephemeral or inaccessible files: `WS-MCHEN-01.../windows_event_sysmon.xml` EventRecordID 525465 at `2024-03-18T14:50:21.1473762Z` is `C:\Windows\System32\runas.exe`; `WS-AJOHNSON-01.../windows_event_sysmon.xml` EventRecordID 31719 at `17:24:44.5475224Z` is `C:\Windows\System32\curl.exe`; and `DC-01.../windows_event_sysmon.xml` EventRecordID 3292079 at `16:00:28.1810736Z` is `C:\Windows\PSEXESVC.exe`. The cluster also includes monitoring agents, Veeam, service payloads, and installers. Under the demonstrated Sysmon hash configuration, resident Microsoft binaries should not systematically lose every configured digest without an accompanying collection failure.

- **`schema_or_format` — negotiated TLS curve details are absent throughout ECDHE telemetry.** Across the three `ssl.json` files, all 879 TLS 1.2 sessions use ECDHE cipher suites, including 624 non-resumed sessions, yet no record carries a negotiated curve. The companion `zeek-dmz/x509.json` has 83 ECDSA certificates with `certificate.key_type="ecdsa"` and `certificate.key_length=256`, but represents `certificate.exponent` as an empty string and supplies no curve field. Zeek version/configuration differences can affect optional columns, so this is lower-weight than the Windows contradiction, but the dataset-wide omission weakens source-native fidelity.

- **`weak_signal` — one application/argument pairing is operationally implausible.** `WS-SMARTINEZ-01.../windows_event_sysmon.xml` EventRecordID 122235 at `2024-03-18T17:27:09.2006629Z` launches `C:\Program Files\Cisco Spark\Webex.exe` with `--url=https://mail.google.com/mail/u/0/#inbox`. That browser destination does not fit a Webex deep-link or meeting invocation and looks like an application path and command-line template drawn independently. It is only one record and is not decisive by itself.

## Evidence For Real

- The corpus has substantial, role-aware volume rather than a thin attack-only slice: 18,529 Windows Security events, 11,690 Sysmon events, 33,946 eCAR records, and 20,261 Zeek connection records over roughly six hours. Domain controllers are dominated by Kerberos and filtering-platform telemetry; workstations have browser, Office, updater, lock/unlock, and endpoint activity; FILE-SRV-01 has SMB object-access auditing; mail hosts have SMTP/Postfix/Exchange activity; and WEB-EXT-01 has web and host-firewall traffic.

- All inspected XML files parsed as XML and all JSON-lines files parsed record-by-record. Security events use the expected provider/channel split and source-native structures, including Event ID 1102 in `UserData/LogFileCleared` rather than forcing it into `EventData`. Event versions and task IDs are consistent: 4624 version 2/task 12544, 4688 version 2/task 13312, 5156 version 1/task 12810, Sysmon 1 and 3 version 5, and Sysmon 5 version 3.

- Windows process correlation is strong and semantically ordered. All 938 Sysmon Event ID 1 process creations except one matched a Security 4688 on the same host, PID, and image within two seconds; matched records also agreed on command line, parent PID/image, and LogonID. The observed Security/Sysmon delay range was about 35–1,242 ms rather than exact equality. Among 760 Sysmon create/terminate pairs, none terminated before creation, none changed PID/image/user for the same ProcessGuid, and dependent network, file, registry, module, process-access, and remote-thread events did not occur outside a known visible lifecycle.

- Windows session semantics are coherent. There are 830 successful logons and 404 logoffs; 397 logoffs map to an earlier visible login with the same LogonID, seven can reasonably be pre-window sessions, and none has a visible matching login only after the logoff. Domain-account SIDs consistently use the same base `S-1-5-21-1524654518-2022274387-1755902678`, with no username mapped to multiple SIDs and no SID mapped to multiple usernames.

- The DC-01 Security log-clear sequence is source-native. `DC-01.../windows_event_security.xml` records Event ID 1102 at `2024-03-18T17:42:01.2672792Z` with EventRecordID 1 and SYSTEM/`0x3e7`; the next visible Security event at `17:42:01.4675710Z` has EventRecordID 2. This correctly models the record-ID reset and uses the Eventlog provider GUID, while the triggering `wevtutil cl Security` appears in Sysmon EventRecordID 3293668 at `17:41:57.1669354Z`, before the clear.

- Zeek linkage is excellent without visible contradiction. All 4,003 DNS, 3,725 HTTP, 2,572 SSL, 2,146 files, 229 SMB-file, 133 SMB-mapping, and 46 SMTP records checked against their same-sensor connection tables had a present UID, matching four-tuple, and timestamps inside the connection interval (with a one-second close tolerance); no tuple or causal-order violations were found. TLS certificate-chain FUIDs resolve to x509 records, adjacent issuer/subject names agree, certificates are valid at capture time, and named SNI values agree with leaf SANs. TLS 1.3 and resumed sessions appropriately account for most records without visible certificate chains.

- Network lifecycle details are credible. In `fw-perimeter/cisco_asa.log`, 6,478 TCP builds have 6,475 teardowns, leaving only three open at the slice boundary. All matched connection IDs retain the same interfaces, addresses, and ports, and every logged `duration` agrees with wall-clock build-to-teardown time. The mix includes `TCP FINs`, `SYN Timeout`, `TCP Reset-O`, and `TCP Reset-I`, with NAT translation create/teardown records around external flows. Snort signatures use compatible protocols and destination ports for DNS, SSH, SMB, and SQL-related detections.

- DHCP behavior is bounded-window realistic. `zeek-core/dhcp.json` contains REQUEST/ACK renewals rather than requiring pre-window DISCOVER/OFFER records. One-hour leases recur with jittered intervals of roughly 1,756–1,989 seconds, two-hour leases around 3,536–3,960 seconds, and four-hour leases around 7,087–7,395 seconds; this is not a rigid exact-period schedule.

- Shell-history texture includes behavior a simplistic chronological renderer often misses. `WS-LNGUYEN-01.../bash_history/lina.nguyen.bash_history` places a `2024-03-18T16:25:03Z` SSH command after a `16:50:06Z` curl command, consistent with concurrent shells appending history on exit. `DB-PROD-01.../bash_history/root.bash_history` also has two commands at the same one-second history timestamp. These are realistic artifacts rather than causal contradictions.

## Detailed Analysis

- **Windows Security and Sysmon:** Field names, versions, localized resource tokens, hexadecimal process/logon IDs, PID divisibility, device paths, parent relationships, and EventRecordID behavior are mostly excellent. Kerberos 4768/4769 records use plausible encryption types (`0x11`, `0x12`, `0x17`), ticket options, IPv4-mapped addresses, service-account names, and DC distribution. Event 4625 status/substatus combinations are sensible (`0xc000006d` with `0xc000006a` for bad password and `0xc0000072` for disabled account). The decisive defect is not schema shape but impossible cross-build Explorer metadata. The globally zero 4689 status population and selective hash gaps add repeatable synthetic texture.

- **Endpoint/eCAR:** Every line parsed, record IDs were unique, and object lifecycle ordering was sound. No visible PROCESS or USER_SESSION object terminated/logged out before its own visible creation/login. Process-dependent events did not occur after a known termination. Many actor IDs do not have a creation inside the six-hour slice, but they predominantly represent long-lived services or pre-window processes; under the bounded-window rule this is not synthetic evidence. The schema supplies host, principal, PID, image, tuple, and directional data consistently, though 1,905 PROCESS/TERMINATE rows contain no exit-code/status property, limiting independent validation of the implausibly uniform Windows 4689 exits.

- **Zeek:** Connection-state and packet semantics were coherent: no `S0` record had responder traffic, no `SF` record had a zero-packet side, no negative duration or payload/IP-byte inversion was found, and protocol records matched connection tuples and intervals. DNS NXDOMAIN records had no answers; certificate FUIDs, x509 issuer chains, validity dates, and SNI/SAN relationships were consistent. The strongest Zeek reservation is the complete absence of negotiated curve data from all ECDHE TLS 1.2 sessions and ECDSA certificate records. This may reflect a narrow logger/configuration choice, so it is not treated as a hard contradiction.

- **Linux/syslog and histories:** RFC 5424 framing, PRI values, host/app/PID fields, six-digit timestamp precision, SSH/PAM wording, Postfix role activity, cron, and role-specific service messages are plausible. Normal SSH sessions have varied connection-to-auth timing and full-microsecond variation. Against that background, the eight failed-session groups constructed from integer-millisecond offsets are conspicuous. The widespread, repetitive `irqbalance` and `snapd` informational traffic is somewhat heavy for servers but remains plausible under verbose daemon settings and therefore was not scored as an independent synthetic indicator.

- **Firewall, IDS, proxy, and web:** ASA message IDs, priorities, connection IDs, NAT ordering, duration rounding, and teardown reasons are strong. UFW blocks align plausibly with ASA embryonic builds/SYN timeouts rather than contradicting them. Proxy and Apache-style records have valid request lines and sensible 304 body handling; Snort signatures align with protocol/port semantics. The Webex/Gmail command line is an isolated behavioral mismatch, not a family-wide failure.

- **Causal ordering:** No visible Zeek dependent preceded its connection start; no paired process or session closed before opening; and service/account/log-clear evidence occurs in a viable order. Missing pre-window initiators were not penalized. High cross-source completeness was treated as neutral-to-positive and was not used as evidence of synthesis.

## Realism Score by Category
- **Field format accuracy:** 8/10 — XML/JSON parseability, Windows event schemas, Zeek tuples, ASA formats, SIDs, PIDs, and source-native tokens are strong; cross-build Explorer metadata, selective Sysmon hash placeholders, and TLS curve omission prevent a higher score.
- **Temporal patterns:** 5/10 — broad event timing, lifecycle ordering, DHCP jitter, and sensor delays are credible, but the 19/24 logon cadence concentration and eight whole-millisecond SSH constructions are strong synthetic fingerprints.
- **Cross-source correlation:** 10/10 — process fields, Zeek UIDs/tuples, certificate FUIDs, firewall lifecycles, and visible session/process ordering showed no concrete contradictions; completeness alone was not penalized.
- **Behavioral realism:** 6/10 — host roles, background activity, authentication, network state mix, and shell-history artifacts are convincing, but all-zero process exits and the Webex/Gmail invocation reduce realism.
- **Environmental consistency:** 6/10 — domain SIDs, host roles, services, addressing, and collection volumes are coherent; the impossible reuse of one OS-bound Explorer binary identity across incompatible Windows build families is a major environmental defect.

## Recommendations

1. Derive metadata and hashes for OS-owned binaries from a host-specific Windows build identity. Add an invariant that `explorer.exe`, `userinit.exe`, `winlogon.exe`, PowerShell, and other system components on one host belong to the same build family, and test Server 2019 (`17763`), Server 2022 (`20348`), Windows 10 (`19041`), and Windows 11 (`22621`) siblings.
2. Replace the fixed logon-chain cadence with host/load/session-dependent timing. Preserve parent order, but model wider and correlated delays for RDP, console, server, and workstation logons; specifically eliminate the repeated 1.35-second and 0.15-second centers across unrelated systems.
3. Timestamp multi-line syslog actions at native precision rather than choosing one microsecond base and adding integer milliseconds. Validate that low-order microsecond digits vary within generated SSH failure sequences whenever the surrounding host clock has microsecond resolution.
4. Populate process exit status from action outcome and command semantics. Include a realistic minority of nonzero 4689 statuses for failed utilities, aborted updates, rejected operations, and terminated processes, and carry the same outcome into normalized endpoint termination fields where the schema permits it.
5. Make Sysmon hash collection internally consistent. With four algorithms enabled, hash resident Microsoft binaries such as `runas.exe` and `curl.exe`; when hashes are unavailable, emit a source-native failure condition tied to a concrete reason rather than selectively using `-` for conspicuous binaries.
6. Validate application-specific command-line grammars and destination types so conferencing clients receive meeting/deep-link URLs and browser destinations are opened by browsers.
7. If the intended Zeek version exposes TLS/x509 curve fields, populate them for full TLS 1.2 ECDHE handshakes and ECDSA keys. If the omission is intentional, preserve a consistent version/configuration profile that explains the absent optional columns.
