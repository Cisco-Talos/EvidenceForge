# Threat Hunter — Authenticity Assessment

## Verdict

**Assessment:** Synthetic  
**Verdict Confidence:** 94  
**Synthetic-Confidence Score:** 84

## Executive Summary

The dataset is unusually strong in field structure, lifecycle ordering, baseline diversity, and cross-source correlation. However, a dataset-wide low-entropy identifier pattern spanning unrelated proxy, endpoint, and mail telemetry strongly resembles a shared generator implementation; command-to-evidence mismatches in the Nmap and reverse-shell activity provide additional independent support for a synthetic verdict.

## Evidence For Synthetic

- `[hard_contradiction]` Probable generator-identity leak across unrelated sources: all 672 unique proxy tunnel identifiers match `PT-00000000[0-9a-f]{8}`, including `PT-00000000d28e8cd5` at 17:25:21 in `PROXY-01.meridianhcs.local/proxy_access.log:2186`. Separately, 119 eCAR file records across six hosts use the same 32-bit-value-in-a-64-bit-slot pattern, `file-00000000[0-9a-f]{8}`. Independent proxy and endpoint products converging on this exact zero-padded construction at that scale is a strong generator fingerprint.

- `[distribution_texture]` All 30 unique Postfix queue IDs extracted from the two mail syslogs begin with `0`. Their lengths vary from 9 to 11 characters, but each contains enough leading zeroes to leave no more than eight varying hexadecimal characters: examples include `01F7818C5`, `0013DA5C71`, and `00026616B3C`. This resembles the same 32-bit identifier source padded to different field widths rather than normal queue-ID entropy.

- `[contract_gap]` The traffic attributed to the visible Nmap commands does not match their command-line semantics. `WEB-EXT-01.meridianhcs.local/ecar.json` records root executing `nmap -sn 10.10.2.0/24` at 13:40:16.909 and `nmap -sT -p 22,80,443,445,3306 10.10.2.0/24` at 13:40:31.801. The first produces exactly one ICMP echo flow for each of 254 addresses, with only nine replies. The second nevertheless produces 1,268 of the possible 1,270 five-port target combinations across all 254 addresses, despite lacking `-Pn`, and has no distinct default discovery-probe texture. This looks like a scan matrix rendered directly from the CIDR and port list rather than traffic generated by the displayed Nmap invocation.

- `[contract_gap]` The exploit command’s required process tree is absent. At 13:20:25.035, `WEB-EXT-01.meridianhcs.local/ecar.json:859` records PID 1480935 running `bash -c 'echo … | base64 -d | bash'`; the decoded content launches another Bash reverse shell. No `/usr/bin/base64`, pipeline Bash, or decoded-command Bash process appears, while the outbound 10.10.3.10:47140 → 45.33.32.30:8443 flow is attributed directly to the outer PID. The same endpoint source captures detailed parent/child processes elsewhere, making omission of every necessary child notable.

- `[weak_signal]` At 17:25:17, the exfiltration `curl.exe` on WS-AJOHNSON-01 is shown with parent `services.exe` running as SYSTEM, while the child is `MERIDIANHCS\aisha.johnson`; Security 4688 places Aisha in the Subject fields and leaves the Target Subject empty. A visible type-9 NewCredentials session makes token switching possible, so this is not an impossible event, but the creator/target-account representation is unusual and received limited weight.

## Evidence For Real

- The source structures are consistently parseable and source-appropriate: all examined JSON and XML records parsed successfully, Windows event versions and data fields vary by event type, RFC 5424 syslog structure is valid, and Zeek packet/IP-byte arithmetic is coherent.

- Cross-source pivoting works with realistic sensor differences. For example, the 17:25 exfiltration appears as WS-AJOHNSON eCAR PID 6980 and Security/Sysmon process events, proxy tunnel `PT-00000000d28e8cd5`, Zeek core UID `CktrLca4mwsauDNqRO`, Zeek DMZ UIDs `CKlPQY0XpT7vWGowjN` and `CakOoCeCDqc49UCjS`, and ASA connection 1688383. The sensors use different UIDs and small clock offsets rather than sharing one synthetic identifier.

- No visible lifecycle inversions were found in the eCAR data: process termination does not precede creation, logout does not precede login, actor processes are not created after their dependents, and no overlapping PID reuse was detected.

- SSH/SCP ordering is technically coherent. On DB-PROD-01, `scp` PID 884810 is created at 17:15:55.988, Zeek sees 10.10.4.10:46919 → 10.10.2.30:22 at 17:15:58.968, APP-INT-01 observes the inbound flow at 17:16:00.751 and login at 17:16:06.698, and the destination file is created at 17:16:35.914 before logout.

- Security-log clearing is represented with convincing native behavior. DC-01 records `wevtutil cl Security` under WMI at 17:42:28–29, followed by Event 1102 at 17:42:33.180 with `EventRecordID=1`; subsequent Security records continue from the reset sequence instead of the earlier 28-million range.

- Baseline network behavior has substantial entropy: Zeek core includes `SF`, `S0`, `RSTO`, `RSTR`, `REJ`, `S1`, `S2`, `S3`, and `OTH` states; DNS includes A, AAAA, TXT, PTR, SRV, NS, MX, and SOA queries with NOERROR, NXDOMAIN, SERVFAIL, and REFUSED outcomes.

- DHCP behavior is appropriately slice-aware and jittered. Six clients have varied lease durations and renewal intervals, including approximately 30-minute, one-hour, and two-hour renewal patterns, plus a skipped interval, without requiring visible initial DISCOVER events.

- Sysmon executable hashes remain stable for the same host and image while differing across some OS/build groups. This is more production-like than independently randomized hashes or one universal hash set.

- The volume and source mix are plausible for the visible scope: 21 endpoints, three Zeek sensor locations, approximately 32,991 eCAR records, 18,232 Security events, 11,542 Sysmon events, 19,833 Zeek connection records, 19,376 ASA messages, 2,524 proxy rows, and 710 web requests over roughly six hours.

## Detailed Analysis

### Scope and collection profile

The visible window is approximately 2024-03-18 12:00–18:00 UTC. The environment contains 21 named endpoints covering workstations, domain controllers, file servers, application/database systems, mail infrastructure, a proxy, monitoring, and an external web tier. Network telemetry is divided among core, DMZ, and database Zeek sensors, with additional perimeter ASA, Snort, proxy, and web-access evidence.

I treated the collection as a slice rather than boot-to-shutdown telemetry. Findings were limited to visible contradictions and repeated source-native patterns; pre-window state, source completeness, and ease of narrating the suspicious sequence were not scored as synthetic indicators.

### Threat-hunting reconstruction

The initial web compromise is operationally coherent. `WEB-EXT-01.meridianhcs.local/web_access.log:435` records 185.70.41.45 posting to `/ehr/admin/upload.php` at 13:20:23 and receiving HTTP 200. The Apache worker then creates the encoded Bash process at 13:20:25.035. Zeek DMZ records the reverse connection at 13:20:28.694 using UID `CJFkITbb7nJ3H1V7nS`, while the ASA builds connection 1683309 at 13:20:28 and tears it down 19 seconds later. Addresses, ports, duration, and byte direction agree.

The attacker later performs discovery from WEB-EXT-01, reads `/root/.ssh/id_rsa`, stages database material through DB-PROD-01 and APP-INT-01, and uses SMB to place it on FILE-LNX-01. The individual SSH and file-transfer lifecycles are well ordered. The defect is specifically in the Nmap command-to-packet contract, not in the fact that discovery exists or is easy to identify.

Windows lateral movement also contains substantial native detail. DC-01 records remote service and WMI activity, creation of `svc_dirsync`, Domain Admins membership modification, service installation, and task registration using appropriate Security event families. Later collection on WS-AJOHNSON-01 creates `cache_7f3a.zip`, and PID 6980 uploads it through the explicit proxy.

The 17:25 exfiltration is particularly well correlated:

- eCAR records PID 6980 reading `C:\ProgramData\Microsoft\cache_7f3a.zip` and connecting from 10.10.1.35:55551 to 10.10.3.20:8080.
- The proxy logs a CONNECT and POST under `MERIDIANHCS\aisha.johnson`, reporting 18,782,974 client bytes.
- Zeek core observes 18,783,277 origin payload bytes on the client-to-proxy leg.
- Zeek DMZ observes the proxy-to-origin leg from 10.10.3.20:47498 with 18,786,007 origin bytes.
- ASA connection 1688383 lasts 26 seconds and reports 19,891,434 total bytes.

The differing byte scopes are sensible for endpoint payload, HTTP transaction, TCP payload, and firewall totals.

### Lifecycle and temporal integrity

Automated lifecycle checks found no visible dependent-before-initiator contradictions for matching process, session, or actor identifiers. Network protocol companions do not precede their corresponding Zeek connections or extend beyond the recorded connection interval. DNS response timing remains within connection duration, and Zeek file references do not precede their associated connection records.

Independent observation timing is modeled convincingly. The same WEB-EXT-01 → DB-PROD-01 transaction at approximately 13:20:25 appears on the DMZ and database sensors with different UIDs and about 173 milliseconds of timestamp separation while retaining matching tuple, byte, and state information. No Zeek UIDs were reused across the core, DMZ, and database sensors.

The Windows Security-log reset is another strong temporal detail: the visible clear command precedes Event 1102, and the record-ID reset occurs at the correct point rather than retroactively affecting earlier records.

### Distribution and baseline texture

The baseline is not globally uniform. Core and DMZ traffic volumes vary substantially between 15-minute intervals, connection durations have thousands of distinct values, and failed connections include realistic mixtures of unanswered SYNs, initiator resets, responder resets, and rejects. Endpoint flows marked `outcome=failure` sampled during review correspond to Zeek `RSTO` or `RSTR` records rather than successful `SF` sessions.

Human and administrative activity also has some long-tail variation. Bash-history overlap across three or more users was limited primarily to generic commands such as `id`, `last -20`, and `systemctl list-units --failed`. Web and proxy traffic include varied client addresses, URI paths, user agents, status codes, destinations, and response sizes.

The major exception is identifier entropy. The exact upper-zero padding shared by proxy tunnel IDs and eCAR file IDs is not an organic behavioral pattern—it is a formatting/identity pattern spanning unrelated systems. The mail queue-ID population independently reinforces that observation.

### Source-native concerns

Most Windows, Zeek, ASA, proxy, web, and syslog fields are syntactically credible. The strongest source-native concern is therefore not malformed JSON or XML, but values that expose a common construction method.

The reverse-shell process tree is a separate semantic issue. The visible outer Bash command cannot execute the encoded pipeline without creating at least the external `base64` process and an additional Bash interpreter. Because the collection captures both the outer process and its resulting flow, as well as detailed child process trees for other commands, complete omission of those necessary stages is difficult to explain solely as a slice boundary.

The Nmap evidence is similarly semantic. The observed traffic is a near-exhaustive direct product of CIDR addresses and requested ports, but the visible command would ordinarily perform host discovery and avoid scanning hosts deemed down unless `-Pn` or an equivalent override were supplied. No such option is present.

## Realism Score by Category

- **Field format accuracy:** 7 — Most source formats are strong, but the shared zero-padded identifier construction is a serious authenticity defect.
- **Temporal patterns:** 8 — Lifecycle ordering, jitter, clock offsets, and connection timing are convincing; the Nmap traffic texture is the main exception.
- **Cross-source correlation:** 9 — Host, tuple, timing, byte, session, and process pivots are generally excellent without impossible visible ordering.
- **Behavioral realism:** 7 — Baseline and attack behaviors are technically rich, but the Nmap semantics and missing reverse-shell child processes are material defects.
- **Environmental consistency:** 8 — Host roles, services, source volumes, failures, DHCP, mail, and background traffic fit the visible environment, apart from identifier conventions shared implausibly across products.

## Recommendations

- If this were synthetic, generate source-native identifiers independently for each product. Avoid formatting 32-bit values as universally zero-padded 64-bit identifiers; model the appropriate alphabet, width, entropy, and allocation behavior for proxy tunnel IDs, endpoint object IDs, and Postfix queue IDs.

- If this were synthetic, expand shell pipelines according to actual process semantics. The encoded reverse-shell command should create the `base64` process and each Bash interpreter, with the socket owned by the process that actually opens `/dev/tcp`.

- If this were synthetic, derive scan traffic from the displayed Nmap options. Either add `-Pn` to justify scanning nearly every address, or emit the default host-discovery probes and restrict the subsequent port scan to hosts Nmap would consider up.

- If this were synthetic, validate Windows alternate-token launches against native 4688 Subject and Target Subject semantics, Sysmon `ParentUser`, logon type, and the actual executable responsible for the launch.
