# Purpose- and type-conditioned canonical file sizes (draft)

New family, distribution_texture: panel7 Threat and all actual deliberators found
15/51 SYSVOL/NETLOGON size-bearing observations above1MiB. Root dedup confirms
14/48 distinct UNC-path/size versions above1MiB (not merely repeated reads): INI
median589476,max8700366; BAT median292137.5,max2803606; PS1 max9890978 bytes.
Large explicit scripts/preferences are possible; this is a population/context
finding, not proof contents are invalid or independent domain GPOs.

Root: StorageWorld._file_size distinguishes backup/software/default only. dc_policy
falls through the generic1KB–12.6MB loguniform size population regardless of file
purpose/type. _compile_catalog owns one size before all transfers; explicit seed
size_bytes is already supplied separately and must remain authoritative.

Owner: canonical StorageWorld file-attribute compilation plus engine-owned typed
config/default loader. Invariant: automatically populated metadata sizes reflect
file purpose/type once, then every SMB/native/file-transfer consumer reuses that
same size and identity/hash. Explicit seeded sizes, observed mutations, multipart/
HTTP byte ownership and raw escape hatches remain explicit, even if large. Match
file-purpose and extension families, never exact example filenames or hostnames.
No Zeek/Syslog emitter-only truncation or packet-accounting fudge.

Entry inventory: auto SMB share populations, default/DC/user/home/department/
software/backup catalogs, pack profile composition/overlays, host filesystem
catalog selection, explicit catalog seeds and later typed file mutations. Inspect
storage_catalog model/validation/cache declarations before choosing configuration
placement; immutable industry/organization packs and authored benchmark hashes
must not change. Consumers: CompiledStorageFile metadata, canonical FileContext,
SMB directory/read/write offsets and transfer durations, Zeek SMB/files and native
SMB client/server audit, eCAR/native file operations, stable contents/hashes and
storage/evaluation manifests.

Sibling plan: canonical type/purpose distributions under all presets, mixed-case
extensions, unknown/custom fallback, script files in software catalogs, text files
in backup catalogs, explicit oversized seed bypass, deterministic config-scoped
cache/overlay and pack composition, one file stable across repeated clients,
partial/full transfer byte budgets, known file-size mutations and fresh-process/
checkpoint equivalence. Data-driven bounded defaults; no new raw continuous RNG
inventory debt or ceiling relaxations. Scope does not claim full GPO hierarchy,
replica synchronization or empirical size calibration without separate evidence.

Read-only design refinement during loop10 generation: portable StorageCatalogData
is a strict public pack vocabulary (directories/subjects/file types). Do not add
engine sizing fields to immutable pack data or alter its public schema to repair
an engine-owned attribute policy. Prefer a separate engine-owned, overlay-aware
activity/storage_file_sizes.yaml with typed cached loader and config validation.
StorageWorld._file_size remains the single numeric sampler so existing scoped
catalog RNG and continuous non-temporal RNG inventory ownership do not move.

Candidate policy routes preset+extension first, then extension, then preset, then
default. This lets scripts stay small in software catalogs and backup archives
stay larger than generic ZIP packages, while unknown custom pack extensions keep
a bounded fallback. Byte support is modeled, not empirical calibration. Explicit
seed sizes bypass auto sizing as before. Configured sizes must have positive
ordered finite bounds and all routing references must resolve; one canonical size
must feed all transfers/source views. Existing byte-range sampling is uniform in
log space, hence nonuniform in bytes; changing to a new unqualified operation
model is not required for this root purpose/type routing repair.

Cache integration finding: new @lru_cache owner must be explicitly included in
config.provider._TRUSTED_DERIVED_CACHE_SLOTS and registered with its exact module/
namespace/wrapper via _register_trusted_derived_cache. Otherwise provider scopes
reject it as untrusted. Follow storage_world._load_catalog_config's existing
pattern and retain replacement/foreign-module fail-closed checks. Include provider
scope/overlay restoration siblings and checkpoint tests; do not weaken generic
cache trust to permit arbitrary new LRUs. An uncached YAML parse per file would
avoid the registry but is not the selected scalable design.
