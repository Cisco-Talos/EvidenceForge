# Host/EDR Forensics Analyst — Authenticity Assessment

## Verdict

**Assessment:** Synthetic  
**Verdict Confidence:** 84/100  
**Synthetic-Confidence Score:** 72/100 — likely synthetic

## Executive Summary

The host and EDR corpus is substantially more realistic than a simple template-generated dataset. Windows Security, Sysmon, and eCAR records use credible schemas and identifiers; process creation and termination are well ordered; hashes remain stable for the same binary; Windows process identities agree across sources; and Linux SSH, Samba, Postfix, and shell activity contain convincing source-native detail. I found no single unambiguous physical impossibility and no basis for a `hard_contradiction` finding.

The synthetic verdict instead rests on a constellation of concrete, repeated defects that cross independent hosts. Webex repeatedly opens Slack or Outlook URLs, while Postman repeatedly opens an Ubuntu Snap API URL. Dynamic-looking SearchFilterHost arguments collapse to only four values across 27 starts. Every Linux host that reports `systemd-resolved` contributes exactly four messages, while other daemon families show similarly fixed per-host quotas. More seriously, Postfix short-lived `smtpd` and `smtp` worker PIDs are reused across four to five hours of unrelated transactions, and eCAR assigns a new USER_SESSION object to each Windows unlock even though the Security channel retains the original logon identity. These are visible generation-contract and distribution fingerprints, not deductions from filesystem metadata, source absence, sanitized domains, or perfect cross-source matching.

## Evidence For Synthetic

- **`environment_or_collection_plausibility` — repeated application/destination mismatches.** In `WS-SMARTINEZ/ecar.jsonl`, PID 7152 at `2024-03-18T14:29:41.556Z` is `C:\Program Files\Cisco Spark\Webex.exe` with command line `"C:\Program Files\Cisco Spark\Webex.exe" --url=https://app.slack.com/client/T01234567`; `WS-SMARTINEZ/sysmon.xml` records the same process at `2024-03-18T14:29:41.3450399Z`. `WS-DRAMIREZ` repeats the exact Webex/Slack pairing at `15:46:54.5963304Z` in Sysmon and `15:46:55.032Z` in eCAR. `WS-AJOHNSON` instead launches Webex with `--url=https://outlook.office.com/mail/` at `14:03:59.8339938Z` in Sysmon and `14:03:59.915Z` in eCAR. Separately, `WS-MCHEN` runs Postman against `https://api.snapcraft.io/v2/snaps/refresh` at `15:07:21.7446274Z`/`15:07:21.881Z`, and `WS-PPATEL` repeats the same incongruent Postman/Snap pairing at `15:42:55.4004318Z`/`15:42:55.535Z`. A single unusual invocation is possible; repetition of multiple wrong application/destination pairings on independent workstations is characteristic of destination-pool assignment without application semantics.

- **`contract_gap` — implausible Postfix worker lifetimes and reuse.** `MAIL-EDGE-01/syslog.log` uses `postfix/smtpd[1969804]` for 45 records from queue/client record `F9E843FA40` at `2024-03-18T12:11:55.629739Z` through queue/client record `3DA544E2C` at `17:29:21.909379Z`, a span of 5 hours 17 minutes. `MAIL-CLIN-01/syslog.log` similarly reuses `postfix/smtpd[439864]` from `12:47:33.935002Z` to `17:29:15.909324Z`. Outbound workers have the same artifact: `MAIL-EDGE-01` reuses `postfix/smtp[1992909]` from `12:54:11.427208Z` to `17:25:07.804337Z`, and `MAIL-CLIN-01` reuses `postfix/smtp[460611]` from `12:47:41.385848Z` to `17:29:23.611631Z`. A long-running `qmgr` PID is normal; repeated reuse of nominally short-lived `smtpd`/`smtp` workers across hours and unrelated, widely separated transactions is not plausible default worker lifecycle behavior absent extreme custom settings.

- **`distribution_texture` — exact daemon-message quotas across unlike Linux systems.** All ten hosts with any `systemd-resolved` records emit exactly four such records during the six-hour window; `DB-PROD-01` emits none. The four-record equality spans workstations, mail servers, a proxy, a file server, a monitoring host, and a public web server despite materially different workloads. For example, `APP-INT-01/syslog.log` has its four resolver records at `12:30:19.437973Z`, `12:34:43.352074Z`, `12:37:02.524832Z`, and `13:02:46.824094Z`; `FILE-LNX-01/syslog.log` has exactly four at `12:10:53.540471Z`, `12:11:09.057337Z`, `12:13:28.229580Z`, and `12:19:08.897851Z`. Ten hosts also have exactly eight `dbus-daemon` records, with `WS-OHADDAD` at six. The messages and times themselves are credible, but the repeated per-host cardinalities are quota-shaped rather than workload-shaped.

- **`distribution_texture` — low-entropy runtime arguments.** Across 27 Sysmon Event ID 1 starts of `SearchFilterHost.exe`, the complete corpus uses only four exact command lines: argument values `804`, `812`, `820`, or `828`, occurring 5, 7, 8, and 7 times respectively across independent workstations. `WS-AJOHNSON/sysmon.xml`, for example, records `SearchFilterHost.exe 0 820 0 0 0` at `12:15:36.0204692Z`, `12:56:10.1639117Z`, and `15:16:04.2207684Z`; `WS-DRAMIREZ` uses `804` at `13:24:20.6199886Z` and `828` at `14:01:38.8785018Z`; `WS-SMARTINEZ` uses `812` at `13:00:05.7135424Z`. Runtime IPC/handle-like parameters repeating from a four-value pool across machines are a concrete templating fingerprint.

- **`contract_gap` — unlocks create new eCAR session objects.** In `WS-MCHEN/ecar.jsonl`, the local interactive login at `2024-03-18T12:27:35.527Z` has object ID `015e306f-b551-4e18-8e77-c537eb235c3a`, logon ID `0x6c6a067`, and session ID 1. The Security channel records a lock at `13:51:00.4410457Z`, then Event 4624 type 7 at `13:59:08.8295193Z` and Event 4801 at `13:59:08.9730083Z`, all retaining that logon/session identity. The corresponding eCAR unlock at `13:59:08.809Z` instead creates object ID `33531003-6cf4-41c1-aa64-85234258833a`; later unlocks at `15:40:46.728Z` and `17:06:46.604Z` create `616cc793-...` and `7af808b5-...` while keeping the same logon ID and session ID. The same split appears on `WS-AJOHNSON`: the `14:27:19.470Z` type 2 login object `4a29294c-...` becomes unlock object `9a4f8a24-...` at `17:34:31.868Z`, although logon ID `0x269710a` and session ID 2 are unchanged. Normal eCAR login/logout pairs preserve object identity, so the unlock behavior violates the corpus's own session-object contract.

- **`environment_or_collection_plausibility` — overlapping local interactive sessions for one user.** `WS-AJOHNSON/ecar.jsonl` has Aisha Johnson's type 2 session 3 from `12:13:58.040Z` to `14:40:32.606Z`, while a second type 2 session 2 begins at `14:27:19.470Z`, creating a 13-minute overlap. Diego Ramirez has type 2 sessions 3 and 1 starting at `12:11:29.653Z` and `12:19:45.295Z`; Sophia Martinez has type 2 sessions 5 and 2 starting at `13:05:24.015Z` and `13:26:49.080Z`; Emily Brooks has type 2 sessions 3 and 2 starting at `16:11:57.292Z` and `16:32:38.563Z`. Concurrent local sessions are technically possible, so this is not a contradiction, but recurrence across ordinary user workstations without accompanying fast-user-switching context is unlikely environmental texture.

- **`contract_gap` — archive commands precede the modeled archive.** In `DB-PROD-01/root_bash_history.log`, root runs `mysqldump ... > /tmp/rpt_0318.sql` at `17:14:54`, then `sha256sum /tmp/rpt_0318.sql.gz` at `17:15:00` and `du -h /tmp/rpt_0318.sql.gz` at `17:15:11`, before `gzip -9 /tmp/rpt_0318.sql` at `17:15:12`. `DB-PROD-01/ecar.jsonl` places the gzip process at `17:15:12.935Z` and the `.sql.gz` FILE CREATE at `17:15:16.883Z`. Failed shell commands or a pre-existing archive could explain the early reads, but the later non-`-f` gzip and modeled creation make that explanation strained. The sequence looks like semantically related commands jittered without enforcing their data dependency.

- **`weak_signal` — systematic SSH EDR observation order.** In all 49 inbound SSH sessions with matching eCAR process and flow observations, the server-side `sshd: user [priv]` PROCESS CREATE precedes the inbound FLOW CONNECT by 186–1,735 ms. For the root DB session, `DB-PROD-01/ecar.jsonl` places the process at `17:14:40.369Z` and flow at `17:14:41.068Z`; `DB-PROD-01/syslog.log` then records the connection at `17:14:43.467071Z`, password acceptance at `17:14:48.876131Z`, PAM open at `17:14:48.970135Z`, and logind session 279197 at `17:14:49.678951Z`. EDR flow publication can lag process telemetry, so this is not a physical contradiction, but the 49-of-49 ordering is a systematic generator/observation fingerprint.

## Evidence For Real

- **High source-native schema fidelity.** Windows Security and Sysmon records carry credible provider metadata, event versions, channel-specific EventRecordIDs, SIDs, GUIDs, hexadecimal LogonIDs, device paths, IPv4-mapped IPv6 addresses, and event-specific fields. Sysmon Event IDs 1, 3, 5, 7, 8, 10, 11, 13, and 22 use plausible versioned field sets rather than a single flattened template.

- **Strong Windows process correlation without lifecycle breaks.** Across the ten Windows hosts, almost every Security 4688 has a Sysmon Event 1 peer with the same PID and image within two seconds; the few missing peers are isolated rather than host-wide. There were no image disagreements among matched records. Sysmon-to-eCAR PROCESS CREATE matching is likewise near-complete with no PID/image disagreements. Wrapper timestamp offsets vary by host and event instead of landing on one constant. Review of thousands of dependent Sysmon events found no use of a ProcessGuid before its visible creation or after its visible termination.

- **Credible process trees and attack-side host behavior.** `DC-01/sysmon.xml` shows `WmiPrvSE.exe` spawning `cmd.exe` and account-management commands before Security Event 4720 creates `svc_dirsync` at `2024-03-18T16:15:11.9587961Z`; Event 4728 adds that same SID, ending `-7538`, to Domain Admins at `16:15:17.3924203Z`. The log-clear chain is also coherent: PowerShell at `17:42:21.7598198Z`, `cmd /c wevtutil cl Security` at `17:42:23.5437677Z`, and `wevtutil.exe` at `17:42:23.7184228Z`. The Security channel then transitions from EventRecordID 28261268 at `17:42:34.3396666Z` to Event 1102, RecordID 1, at `17:42:34.7208375Z`, followed by post-clear records. This is a convincing Windows lifecycle rather than a loose collection of suspicious event IDs.

- **Stable, plausible binary identity.** The same executable path never changes hash on the same host during the window. Shared products such as Teams and Zoom have matching hashes where the binary is shared, while Windows components retain plausible host/version variation. This is internally disciplined and source-consistent.

- **Detailed Linux SSH lifecycle.** The DB root session correlates source tuple, server PID, account, PAM state, logind session 279197, eCAR USER_SESSION login at `17:14:49.015Z`, and shell creation at `17:14:51.359Z`. The connection, acceptance, session-open, shell, command, and close phases are distinct rather than compressed into one synthetic row.

- **Convincing Samba sequencing.** `FILE-LNX-01/syslog.log` records Marcus Green's Kerberos authentication at `12:04:12.548Z`, share connection by `smbd[2665970]` at `12:04:12.609Z`, open at `12:04:12.953Z`, read at `12:04:13.128Z`, close at `12:04:13.218Z`, and disconnect at `12:04:15.115Z`. PID, user, share, and operation sequencing remain coherent.

- **Source-native Postfix transaction chains are otherwise strong.** Queue `F9E843FA40` on `MAIL-EDGE-01` moves from smtpd client receipt at `12:11:55.629739Z`, through cleanup/message-id at `12:11:56.271Z`, qmgr at `12:11:57.124Z`, local and SMTP delivery records, to removal at `12:12:03.188Z`. Queue IDs, recipients, delay components, and daemon roles fit normal Postfix semantics even though worker PID reuse does not.

- **Role-aware Linux behavior.** Shell histories and syslog mixes differ materially by system role: development activity uses Git, npm, Docker, and Cargo; analyst activity uses pandas, MySQL, and PostgreSQL tooling; mail hosts use Postfix/Dovecot commands; the file server carries Samba activity; and the public web server carries substantially more firewall traffic. No exact shell command was repeated across four or more history files, and no three-command sequence was cloned across hosts.

## Detailed Analysis

**Windows process and session model.** Process-create evidence is the corpus's strongest layer. PID, image, parent, user, ProcessGuid, hash, and eCAR actor identity remain internally consistent. Process termination follows creation, and dependent file, registry, network, load-image, and access events stay inside the visible lifetime. Security 4688 and 4689 records track the same lifecycles with realistic subsecond collection offsets. Session records preserve SIDs and LogonIDs through lock/unlock in the Security channel. The principal weakness is not raw Windows formatting but higher-level session construction: repeated overlapping local logons and eCAR's creation of fresh session objects for unlocks.

**System lifecycle.** Normal services, WMI descendants, userinit/explorer trees, remote-service activity, account changes, and audit-log clearing form plausible causal chains. EventRecordIDs increase monotonically except where DC-01's visible Event 1102 log-clear resets the Security channel, which is expected. Host activity is bounded naturally at the review window, and no conclusion was drawn merely from missing start/end events at the edges.

**Linux evidence.** Syslog syntax, hostnames, program/PID notation, SSH/PAM/logind sequencing, Samba actions, Postfix queue flow, and command histories are source-aware. Workloads differ by host role and are not globally uniform. The realism drops at the population level: resolver, dbus, and other background-daemon families repeatedly hit exact host quotas; verbose background messages are distributed more like catalog selections than emergent daemon operation; and Postfix worker identities remain fixed far beyond credible per-process transaction lifetimes.

**EDR correlation.** eCAR does a good job reusing Windows process identity and producing source-aligned file, registry, flow, and session observations. This is evidence for quality, not by itself evidence for synthesis. The negative evidence is specific: eCAR violates its own stable-object convention on Windows unlocks, and every inspected inbound SSH session publishes server process creation before its inbound flow. The latter can arise from collector latency, but its universal direction and narrow lag range make it a useful weak fingerprint.

**Behavioral texture.** Interactive commands, business applications, admin actions, and role-specific tooling are varied. However, application/destination pairings sometimes ignore application semantics, and these mistakes repeat exactly across users. The four-value SearchFilterHost argument pool, exact daemon quotas, and recurring dual local sessions further indicate that individually realistic elements were sampled from bounded generators.

**Alternative real-data explanation.** Sanitization can explain domains and normalized organization names, and central collection can explain small inter-source delays. Custom Postfix settings, fast user switching, and failed shell commands can each explain one anomaly. They do not parsimoniously explain the complete set: hours-long reuse of multiple short-lived Postfix worker classes, exact cross-role daemon quotas, repeated wrong-app URL launches, a four-value runtime argument pool, and reproducible eCAR unlock identity splitting. The combined evidence moves the corpus above “mixed/inconclusive” while stopping short of “confidently synthetic” because source-native structure and lifecycle correlation are unusually strong.

## Recommendations

- Model Postfix `smtpd`, `smtp`, `local`, and cleanup worker creation, reuse limits, idle timeout, and exit independently; reserve long-lived stable PIDs for daemons such as master and qmgr.
- Bind destinations and command-line arguments to application semantics. Webex should not receive Slack/Outlook browser URLs, and Postman should not receive an Ubuntu Snap refresh endpoint unless an explicit developer workflow supports it.
- Generate runtime IPC/handle-like arguments from process- and host-scoped state rather than a four-value global pool.
- Drive Linux background daemon events from host role, elapsed state, traffic, failures, retries, and daemon-specific timing, avoiding identical per-host record quotas.
- Preserve one eCAR USER_SESSION object across login, lock, unlock, and logout; represent lock state as an action or state transition rather than a new session object.
- Enforce data dependencies in command narratives: archive checksums and size checks should follow successful archive creation, with failed-command evidence emitted when an early check is intentional.
- Prevent overlapping type 2 sessions for the same ordinary workstation user unless fast-user-switching or multi-session context is modeled explicitly.
- Vary source-observation ordering for SSH according to actual sensor semantics, while keeping canonical transport establishment before server-side accepted-session activity.
