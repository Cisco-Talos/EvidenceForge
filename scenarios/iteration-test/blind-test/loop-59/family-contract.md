# Native sensitive-logon privilege membership

Classification: sibling_defect / shared auth data policy. Owner: canonical authentication privilege selection, validated data-driven native4672 profiles and their compatibility adapter. AuthContext.privilege_list is already the event-specific sensitive list, not an arbitrary full token inventory. Current profiles/fallbacks mix ChangeNotify, IncreaseWorkingSet, TimeZone, Shutdown and Undock into4672; these rights are not in its native sensitive set. The elevated-user pool contains no sensitive rights and must not invent a special-privilege event.

Invariant: canonical profiles contain only the configured native sensitive allowlist; validate profile membership and duplicate/unknown entries. An empty profile is allowed and produces no4672. One shared loader supplies normal generation and low-level fallback; remove independently hardcoded renderer lists. Retain explicit raw-native rows. Preserve SYSTEM/service/domain/workstation distinctions and the valid modern DelegateSessionUserImpersonate right; do not confuse older documentation omission with invalidity.

Entry paths: interactive/network/service/DC logons, machine accounts, elevated regular-user tokens, raw compatibility AuthContext and config overlays. Verify siblings with nonempty and empty profiles, loader reset, negative validate-config and actual emitted rows. Sources: Microsoft4672 field-specific sensitive list https://learn.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4672 ; sensitive-use policy https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/audit-sensitive-privilege-use . Modern DelegateSessionUserImpersonate presence is corroborated by firsthand4672XML export (observational primary, not specification): https://learn.microsoft.com/en-us/answers/questions/3251196/event-4672-special-logon . Profile intent is event-native membership, not a change to account group membership or elevated-token truth.
